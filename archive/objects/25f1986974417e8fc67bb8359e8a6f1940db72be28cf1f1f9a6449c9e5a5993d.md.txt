# Codex Orbit 사용 설명 · 10차 / 버전 1.5.2

실행하면 투명 배경의 무채색 입체 궤도가 화면 위에 나타납니다. 세 원형 궤도는 XYZ 회전·원근 투영·깊이순 가림과 금속 명암으로 움직입니다. 외곽과 중앙 허브는 1:1 원형입니다. 나눔고딕 Bold 글꼴을 내장하며 인터넷으로 대화 내용을 전송하지 않습니다.

## 궤도 조작

- 마우스로 드래그하면 위치를 옮깁니다. 다음 실행에서도 위치를 기억하고, 모니터가 바뀌어 화면 밖에 놓이면 보이는 화면으로 복구합니다.
- 궤도를 클릭하면 변경 이력이 열립니다. 우클릭하면 설정과 종료 메뉴가 나옵니다.
- 중심 아래 작은 점은 정상 감시일 때 회색, 새 변경이 있을 때 흰색이며, 감시 오류·준비 중에는 어두운 점 안에 가로선을 표시합니다. 정확한 감시 상태 문구는 상세 창에서 확인합니다.
- 새 변경의 말풍선을 클릭하면 그 알림의 정확한 이력을 엽니다. 새 항목이 추가돼도 다른 항목으로 바뀌지 않습니다. 기본 표시 시간은 30초이며, 설정의 ‘알림을 직접 닫을 때까지 유지’를 켜면 닫기를 누를 때까지 유지합니다.
- 변경마다 별도 말풍선이 즉시 나타납니다. 앞 알림을 닫을 필요가 없습니다. 화면 안에 세로로 쌓고 공간이 부족하면 어긋나게 겹칩니다. 새 알림을 가장 위에 표시하며 각 창의 닫기·클릭·자동 만료는 다른 창에 영향을 주지 않습니다. 같은 ID의 갱신은 기존 창을 보강하고 표시 시간을 초기화하지 않습니다. 이력 다시 보기는 같은 창이 있으면 갱신하고 없으면 즉시 새 창으로 엽니다.
- 동시에 최대 8장을 표시합니다. 초과하면 가장 오래된 창만 숨기고 새 알림은 바로 표시합니다. 숨긴 누적 건수는 말풍선과 이력 상단에 안내합니다. 이력에서 다시 볼 수 있으며 화면 이력은 최근 500건, 파일 보존에는 아래 순환 상한이 적용됩니다.
- 채팅 제목을 맨 위에 크게 표시하고 모델 변경·추론 강도 변경·모델·추론 변경을 구별합니다. 이전 값과 새 설정을 위아래로 비교하며 새 설정을 강조합니다. 강도는 없음 (none), 최소 (minimal), 낮음 (low), 보통 (medium), 높음 (high), 매우 높음 (xhigh), 최고 (ultra)처럼 원문과 함께 표시합니다. 한글은 앱의 표시 편의이며 공식 품질 보증이 아닙니다. 모델 ID·공개 이유 원문은 상세에 보존하고 확인되지 않은 이유는 만들어 넣지 않습니다.
- 같은 감시 묶음은 유효한 원본 시각 순으로 전달하고 시각이 같으면 감지 순서를 유지합니다. 시각이 없거나 잘못되면 감지 위치를 유지하고 이미 표시한 알림은 뒤늦게 읽은 파일로 재정렬하지 않습니다.
- 밝은 화면에서는 ‘밝은 배경’, 어두운 화면에서는 ‘어두운 배경’ 대비를 선택할 수 있습니다.

## 실시간 Codex 잔량

외곽 눈금·진행 링·빛 이동은 장식 모션입니다. 중간 애니메이션 값을 계정 수치로 표시하지 않습니다. 확인된 숫자는 반올림 애니메이션 없이 즉시 표시합니다.

중심 숫자는 현재 로그인된 Codex 계정의 남은 **사용 한도 비율**입니다. 남은 토큰 개수를 뜻하지 않습니다. 여러 버킷·기간이 있으면 확인된 값 중 가장 적게 남은 비율을 중심에 표시합니다. 상세 창 상단에서 각 버킷의 기간별 잔량 막대·초기화 한국 시각·최종 조회 시각을 확인할 수 있습니다. 서버가 주간 한도만 주면 주간만 표시하며 없는 5시간 한도를 만들지 않습니다.

앱은 PC에 설치된 Codex의 공식 App Server를 별도 숨김 프로세스로 연결하여 읽기 전용 `account/rateLimits/read`만 조회합니다. 최초 실행 후 30초마다 자동 조회하며 ‘새로고침’을 눌러 수동 조회할 수 있습니다. 서버가 사용 한도 변경을 알리면 반영합니다. 실제 조회 지연과 서버 반영 시차가 있으며 매 순간의 확정값은 아닙니다. 연결 중에도 궤도 회전·드래그와 기존 알림 기능을 사용할 수 있습니다.

아직 한도를 받지 못했거나 수치가 없으면 중심은 ‘—’입니다. 조회 실패·지연 또는 초기화 시각 경과 후 재조회 전에는 과거 수치를 현재값으로 표시하지 않으며, 이전 수치가 있으면 중심에 ‘?’와 상세에 ‘이전 조회 값’을 표시합니다. 초기화 시각이 지났다고 임의로 100%로 바꾸지 않습니다. 잔량을 디스크에 캐시해 다음 실행에 복원하지 않습니다.

설치된 Codex에서 ChatGPT 로그인이 되어 있어야 합니다. 앱은 로그인·계정 선택·리셋·크레딧 구매·모델 실행·Codex 설정 변경을 하지 않으며 인증 파일을 직접 읽거나 복사하지 않습니다. 연결 실패 시 세 차례까지만 자동 재연결하며 수동 새로고침으로 다시 시도할 수 있습니다. Codex EXE 자동 탐색이 실패하면 ‘설정 · 진단’의 ‘Codex EXE 선택’에서 설치된 `codex.exe`를 선택하고 저장하세요. 비워 저장하면 자동 탐색으로 돌아갑니다. API 키를 입력하는 기능은 없습니다.

## 모델 변경 감시와 근거

기본은 CODEX_HOME 환경변수 또는 사용자 홈의 .codex/sessions 폴더입니다. 설정에서 실제 sessions 폴더를 선택할 수 있습니다. 최초 실행은 기존 기록을 기준선으로 읽으므로 과거 알림을 쏟아내지 않습니다. 폴더별 상태가 별도로 보존됩니다.

Codex가 채팅 ID와 함께 남긴 선택 설정 기록을 읽어 모델·추론 강도 변경을 다음 메시지 실행 전에 감지합니다. ‘채팅 선택 설정 변경’은 설정 관측이며 사용자가 바꿨다는 사실이나 서버 실행 모델을 인증하지 않습니다. 일반·계획 모드의 활성 모델과 추론 강도를 비교하고, 같은 설정 반복이나 뒤따르는 동일 turn_context는 중복 알림을 만들지 않습니다. 실제 로컬 실행 관측이 선택값과 다르면 별도로 남깁니다. 부모에서 상속한 다른 채팅의 설정·턴은 자식의 변경으로 처리하지 않습니다.

감시 주기 대기는 200ms입니다. Codex가 기록하기 전의 화면 선택이나 서버 내부 변경을 알 수 없으며, 큰 파일을 나누어 읽는 시간과 화면 처리 시간 때문에 전체 알림 지연이 200ms 이하라고 보장하지 않습니다. 같은 sessions 루트 아래 날짜·프로젝트·자식 채팅을 감시하지만 탐색은 기존처럼 최대 4096개 파일로 제한됩니다.

이전 감시 상태를 처음 열면 원본 state를 별도 백업하고 이미 읽은 위치까지만 선택 설정 기준선을 재생합니다. 과거 이력·중복 방지 기록을 초기화하지 않습니다. 재생 시작 뒤 추가된 설정은 새 변경으로 처리하며 중간 종료 후에는 저장된 위치에서 이어갑니다. 남은 기존 기록이 있으면 ‘기준선 준비 중’과 잔여 바이트를 진단에 표시합니다.

감지 시각은 앱이 변경을 발견한 시각이며, 원본 turn_context의 시각은 별도 보존해 상세에서 표시합니다. 파일 읽기 예산 때문에 뒤늦게 발견한 항목과 이미 전송한 알림 사이의 전체 시간순까지 보장하지 않습니다. 비교할 수 없는 시각을 현재 시각으로 만들어 정렬하지 않습니다.

채팅 제목은 sessions와 같은 상위 폴더의 session_index.jsonl에서 읽습니다. 앱 데이터 폴더의 title-cache.json에 공식 앱에서 확인한 제목을 저장하면 그 확인 캐시를 우선합니다. 출처와 확인 시각은 상세에 남으며 현재 실시간 조회로 표현하지 않습니다. 자식 작업에는 부모 채팅의 정확한 제목과 별도 작업 이름을 표시합니다. 확인할 수 없으면 ‘채팅 제목 확인 불가’로 표시하며 첫 프롬프트나 폴더명을 제목으로 만들지 않습니다.

공개 이유는 부모의 공개 설명과 spawn 호출 ID·호출 결과·자식 작업 경로가 정확히 연결된 첫 배정에서만 보강합니다. 명시 요청에 모델·강도가 있으면 관측값과 대조합니다. 부모가 늦게 읽히면 기존 이력을 보강하며 과거 알림을 다시 만들지 않습니다. 최근 부모 기록은 파일당 최대 4 MiB, 주기당 추가 8 MiB 안에서 우선 조회합니다. 범위 밖의 호출은 순차 감시를 기다리므로 즉시 이유를 찾지 못할 수 있습니다. 기록에 공개 이유가 없거나 연결 근거가 부족하면 ‘확인 불가’입니다. 다른 도구가 공개 설명과 배정 사이에 있으면 자동으로 이유를 추정하지 않습니다. 로컬 기록이나 명시 배정 요청은 서버 모델 신원 인증이 아닙니다. 비공개 추론을 추출하지 않습니다.

기본 카드에는 채팅 제목·작업·전후 모델과 추론 강도·한국 시각·짧은 공개 이유가 나옵니다. 짧은 이유는 명시된 ‘이유:’ 문장과 배정·선택의 목적 또는 원인이 적힌 원문 문장을 우선 발췌합니다. 이런 문장이 없으면 첫 문장을 표시합니다. 첫 문장이 짧은 ‘맡기겠습니다/배정하겠습니다’ 예고이면 다음 원문 문장을 발췌하며 자동으로 원인을 만들어 요약하지 않습니다. ‘원문 · ID · 근거 펼치기’에서 전체 이유와 ID·출처를 볼 수 있습니다. 자식 첫 배정은 같은 자식 내부의 모델 변경과 구분됩니다. 앱 표시 요청과 사용자가 실제 화면을 읽었다는 확인은 다릅니다. 모바일 ChatGPT 푸시나 Windows 알림 센터 보관을 제공하지 않습니다.

이력은 화면에 최근 500개를 표시하며 파일 읽기도 최대 2 MiB로 제한합니다. 감시기는 파일당 읽기 예산과 전체 읽기 예산을 두고 큰 파일을 나누어 읽으므로 새 변경 감지가 지연될 수 있습니다. 이력·진단은 2 MiB 초과 시 이전 파일 하나를 보존하며 순환합니다. 전체 영구 보관이 아닙니다. 설정·진단 탭에서 최근 오류를 확인할 수 있습니다.

감시 작업자가 20초 이상 진행 상태를 보내지 않으면 상세 창에 ‘감시 지연’과 가로선이 있는 상태점을 표시합니다. 종료가 확인된 작업자는 간격을 늘려 세 차례까지 다시 시작합니다. 실행 중인 정체 작업자는 강제 종료하지 않습니다. 상태가 오래 멈춰 있으면 설정을 확인하고 앱을 정상 종료 후 다시 실행하세요. 모든 모델 변경이 로컬 기록에 즉시 남는다는 보장은 없으며 최초 정체의 모든 원인을 자동 수리하는 기능은 아닙니다.

상태 저장은 호출별로 다른 임시 파일을 쓰며, Windows 공유 오류일 때 최대 다섯 번까지 교체를 시도합니다. 재시도 사이 대기는 합계 0.26초이고 실제 파일 입출력 시간은 별도입니다. 끝까지 실패하면 기존 상태 파일을 보존하고 오류를 표시합니다. 진단 파일도 저장할 수 없으면 원래 오류와 진단 저장 오류를 메모리에 최근 다섯 건까지 함께 보존해 화면에 보여 주며 다음 주기 감시를 계속합니다. 잠금이나 접근 문제가 해소돼야 저장이 회복될 수 있습니다. 전원 차단이나 표시 요청 직후 이력 저장 실패 시 재알림 가능성은 남습니다.

필수 감시 준비가 실패하면 회전 위젯을 남기지 않고 시작 오류를 안내합니다. 준비 완료 뒤에도 첫 정상 진행 상태를 받기 전에는 정상 감시 점을 표시하지 않습니다. 앱 데이터 폴더의 `startup.jsonl`에는 시작·감시 단계, 실제 PID, 시각, 실행·데이터·세션 경로와 오류를 남깁니다. 기록 자체의 저장 실패도 진단에 표시하며, 손상된 캐시나 상태를 자동 초기화해 숨기지 않습니다. 과거 17:32 정지의 최초 원인은 당시 증거가 없어 여전히 미확정입니다.

`notice-presentations.jsonl`에는 말풍선 표시 요청 시각과 이벤트 ID·대상·모델·강도·원본 시각·동시 표시 수를 기록합니다. 대화 본문·제목·공개 이유는 포함하지 않습니다. `display_requested`는 앱의 표시 요청이며 `user_confirmed`는 항상 false입니다. 사용자가 실제로 읽거나 클릭했다고 인증하는 기록은 아닙니다. 기록 쓰기에 실패해도 독립 말풍선 표시는 계속 진행하고 진단에 실패를 표시합니다. 이 기록과 시작 기록도 2 MiB를 넘으면 이전 파일 하나만 보존하며 순환합니다.

‘종료’를 누르면 잔량 연결을 정리하고 감시 작업자에 중단을 요청합니다. 진행 중인 읽기가 끝날 때까지 화면 응답을 유지하며, 실제 작업자 종료 신호를 받은 뒤 앱을 종료합니다. 종료 중에는 감시기를 다시 시작하지 않습니다. 작업자가 운영체제 입출력에서 계속 정체되면 정상 종료 완료가 늦어질 수 있습니다.

## Markdown 지침

앱의 파일·폴더 선택창과 메시지·우클릭 메뉴는 같은 무채색 테마를 사용합니다.

‘MD 지침’ 탭에서 기본 지침을 읽거나 임의의 UTF-8 Markdown 파일을 가져와 편집할 수 있습니다. 잘못된 UTF-8과 2 MiB 초과 파일은 오류로 표시합니다. 내보내기는 UTF-8로 저장합니다.

프로젝트 폴더 또는 사용자 지침을 선택하면 대상 AGENTS.md 경로를 확인할 수 있습니다. 적용 미리보기에서 적용 후 전체 문서를 확인하고 ‘미리본 대상에 명시 적용’을 눌러야 파일이 바뀝니다. 기존 원문 바이트는 앱 데이터의 backups에 보존합니다. 기존 내용은 유지하고 CODEX-ORBIT 관리구역만 추가·교체합니다. 심볼릭 링크·정션·재분석 경로에는 적용하지 않습니다.

미리보기 뒤 대상이 바뀌면 적용을 거부합니다. 새 미리보기를 확인해 주세요. ‘백업 선택 · 원복’은 적용 후 현재 해시가 그대로일 때만 원문 바이트를 복원합니다. 그 뒤 직접 바꾼 파일은 덮어쓰지 않습니다. 새로 만든 AGENTS.md를 원복하면 해당 새 파일을 제거합니다. 백업 파일은 남습니다.

지침 파일 저장은 열린 대화의 재주입, 계정·기기 동기화, 권한 증가, 자동 모델 전환을 보장하지 않습니다. auth, config, hooks와 신뢰 설정은 수정하지 않습니다.

## 데이터와 배포

앱 설정·위치·감시 상태·이력·백업은 기본적으로 현재 사용자의 LocalAppData/CodexOrbit에 저장합니다. 배포 EXE에 개인 대화·원본 개인 지침을 포함하지 않습니다. 제거 프로그램은 사용자 지침과 이력을 삭제하지 않습니다.

시험 실행에는 --data-dir, --sessions를 지정할 수 있습니다. --smoke-test --smoke-report 경로 옵션은 약 1초 동안 두 프레임의 변화·투명 모서리·내장 글꼴을 검사하고 JSON을 저장한 뒤 종료합니다. 실제 사용자 알림 수신의 증거는 아닙니다.

`--usage-smoke-test --smoke-report 경로`는 실제 잔량 서버를 조회해 정규화한 한도·화면 표시·스크린샷을 저장하고 종료하는 별도 진단입니다. 18초 안에 받지 못하면 실패로 종료합니다. 기본 `--smoke-test`는 잔량 서버와 네트워크 조회를 시작하지 않습니다. 이 진단의 JSON 저장은 명시 실행한 시험 결과이며 앱이 잔량을 복원하는 캐시가 아닙니다.

시작할 때 --show-event 이벤트ID 또는 대상ID를 지정하면 기존 이력을 ‘기록 다시 보기’로 표시합니다. 새 관측을 만들지 않으며 이미 실행 중인 앱에 명령을 전달하는 기능은 아닙니다.


긴 알림 제목은 화면 안에서 가능한 높이까지 표시합니다. 화면을 넘는 제목은 말줄임표로 구분하며 마우스를 올리거나 정확한 변경 상세를 열면 전체 제목을 확인할 수 있습니다. 원본 제목·이력은 축약하지 않습니다. MD 지침 탭은 전체 본문을 세로로 스크롤하며 작은 창에서도 편집 영역140px·미리보기100px 이상의 높이를 유지합니다.

설정을 저장하면 이전 감시 작업자에 정상 종료를 요청하고, 실제 종료 신호 뒤 최종 저장한 설정으로 한 번 재시작합니다. 연속 저장은 마지막 설정을 사용하며 의도적인 재시작은 오류 재시도 횟수를 소모하지 않습니다. 안내는 재시작 대기 또는 감시 준비로 구분하며, 첫 정상 진행 상태를 받은 뒤에만 감시 중으로 표시합니다. 앱 종료 중에는 예약된 재시작을 취소하고 실제 오류에 대한 기존 자동 재시도 상한3회는 유지합니다.
