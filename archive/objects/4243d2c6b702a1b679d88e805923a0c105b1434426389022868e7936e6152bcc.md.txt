# Codex 모델 변경 Windows 알림

현재 사용자 `.codex/sessions` JSONL을 읽기 전용으로 감시합니다. 외부 전송, Codex 설정·훅·인증·권한 변경은 없습니다. 프로그램과 상태는 이 폴더에 있습니다.

## 사용

이 PC에서 설치·시작·중지·제거 스크립트는 이미 RemoteSigned인 번들 PowerShell 7로 실행합니다. Windows PowerShell 5.1의 `-File` 실행은 기존 Restricted 정책 때문에 차단되었으며 정책을 변경하지 않았습니다.

```powershell
& 'USER_HOME\.cache\codex-runtimes\codex-primary-runtime\dependencies\native\powershell\pwsh.exe' -NoProfile -File '.\설치.ps1'
& 'USER_HOME\.cache\codex-runtimes\codex-primary-runtime\dependencies\native\powershell\pwsh.exe' -NoProfile -File '.\시작.ps1'
```

`설치.ps1`은 현재 사용자 시작 메뉴에 전용 AppUserModelID `Yunseok.Codex.ModelChangeNotifier`와 로그인 자동 시작 바로가기를 등록하며, `HKCU\Software\Classes\AppUserModelId\Yunseok.Codex.ModelChangeNotifier`에 이 앱의 DisplayName·IconBackgroundColor만 등록합니다. 다른 앱 ID나 COM 활성기를 사용하지 않습니다. 알림 클릭으로 앱을 여는 기능은 제공하지 않습니다. 설치는 실행을 시작하지 않습니다. `시작.ps1`은 pythonw로 숨김 시작합니다. `중지.ps1`은 다음 감시 주기의 정상 종료를 요청합니다. `제거.ps1`은 정상 중지 요청과 이 프로그램의 바로가기 두 개·전용 앱 ID 표시 정보만 제거하며 이력·소스를 보존합니다. 관리자 권한은 사용하지 않습니다.

기본 Python은 `USER_HOME\.cache\codex-runtimes\codex-primary-runtime\dependencies\python\python.exe`이며 시작·설치는 같은 폴더의 pythonw.exe를 사용합니다. 위치가 바뀌면 설치·시작의 `-PythonPath`를 지정하세요. 상태 확인은 아래 명령을 이 폴더에서 실행합니다.

```powershell
& 'USER_HOME\.cache\codex-runtimes\codex-primary-runtime\dependencies\python\python.exe' -B -X utf8 src/notifier.py status
& 'USER_HOME\.cache\codex-runtimes\codex-primary-runtime\dependencies\python\python.exe' -B -X utf8 src/notifier.py test-toast
& 'USER_HOME\.cache\codex-runtimes\codex-primary-runtime\dependencies\python\python.exe' -B -X utf8 src/notifier.py history
```

`test-toast`는 호환 명령 이름이며 현재 전송 방식은 Microsoft Windows Forms의 `NotifyIcon.ShowBalloonTip`입니다. 전용 앱 ID를 현재 전송 프로세스에 지정하고 Windows Shell의 `BalloonTipShown` 이벤트를 확인합니다. 8초 안에 이 이벤트가 오지 않으면 실패로 처리하며 대기 알림을 보존합니다. 전역 알림 정책·집중 모드·실행 정책을 바꾸지 않습니다. 기존 WinRT 토스트는 전용 바로가기·표시 정보·프로세스 ID 연결 뒤에도 `get_Setting()`이 `0x80070490`을 반환하여 현재 전송 경로에서 사용하지 않습니다. 이 오류의 Windows 내부 원인은 확정하지 못했습니다.

알림 제목은 최대 63, 본문은 최대 255 UTF-16 단위입니다. 대상·변경 전후·이유·근거를 표시하며 긴 항목의 끝은 `…`로 발췌합니다. 한글과 이모지의 문자 경계를 지킵니다. 원래 모델 값과 전체 이유는 기존 `work/history.jsonl`에 보존하며 `history`는 이 **로컬 전송 이력**을 읽습니다. Windows 알림 센터 이력을 조회하거나 센터 저장을 보장하는 기능은 아닙니다. 실제 표시 시간·모양·글꼴은 Windows가 결정합니다. 표시 이벤트 확인도 실제 사용자가 화면을 보고 수신했다는 확인과 다릅니다.

명시적 이유를 배정 시 함께 기록하려면 실행 중인 감시기 대상으로 아래처럼 입력합니다. 공개 이유를 로컬 큐에 저장하고 근거를 '명시적 배정 기록'으로 표시합니다. 이것은 서버 모델 증명이 아닙니다. 대상에는 실제 세션 UUID를 지정하세요. 같은 대상·같은 모델/강도에는 알림을 반복하지 않습니다.

```powershell
& 'USER_HOME\.cache\codex-runtimes\codex-primary-runtime\dependencies\python\python.exe' -B -X utf8 src/notifier.py announce --target '실제 세션 UUID' --before-model 'gpt-6.1-sol' --before-effort 'medium' --after-model 'gpt-6.1-sol' --after-effort 'high' --reason '독립 검증에 필요한 검사 범위를 확인하여 검증 역할을 배정했습니다.'
```

## 감지와 한계

상태 형식 2는 실제 `turn_context` 기준선(`models`)과 명시 요청(`declarations`)을 분리합니다. 요청 B를 기록해도 실제 A 기준선은 유지되므로 다음 실제 C 관측은 A→C이며, 실제 A 유지에는 가짜 변경을 알리지 않습니다. 요청의 전후와 다음 관측 전후가 모두 일치할 때는 중복 알림을 생략하고 `work/observations.jsonl`에 실제 관측 근거와 원래 요청 ID를 남깁니다. 이 파일도 2 MiB 순환 이력입니다. 요청 이력을 나중에 실제 관측이었다고 바꾸지 않습니다. 같은 주기의 관측 대기 알림과 요청 전후가 정확히 일치하면 한 알림에 명시 이유를 병합하며 원래 관측 근거를 별도 필드에 보존합니다. 다른 실제 변경이 먼저 발생하면 오래된 요청 연결은 폐기합니다.

형식 번호가 없거나 2가 아닌 상태는 요청과 실제 관측의 혼합 여부를 판별할 수 없어 시작을 거부합니다. 기존 감시기를 정상 중지한 뒤 `work/state.json` 원본을 아카이브하고 상태 파일이 없는 조건에서 명시적으로 재기준선을 준비해야 합니다. 과거 대기 요청의 자동 이관은 제공하지 않으므로 아카이브 내용을 먼저 검토해야 합니다. 중앙 `.codex` 라우팅 누적 상태는 이 절차의 대상이 아닙니다.

첫 실행의 기존 기록은 당시 파일 바이트 끝을 고정한 기준선만 만들고 알리지 않습니다. 그 뒤 붙은 기록은 기준선 읽기가 완료된 다음 알립니다. 이후 새 세션의 첫 배정과 `turn_context.payload.model` 또는 `effort` 변화를 알립니다. 실제 기록 전의 GUI 설정 변경과 로그에 남지 않는 서버 내부 변경은 즉시 감지할 수 없습니다. 로컬 런타임 기록 관측이며 서버 신원 인증이 아닙니다.

첫 자식 배정은 부모의 바로 직전 공개 commentary와 spawn_agent의 call_id, 대응 호출 결과 task_name, 자식 메타의 parent_thread_id 및 agent_path를 정확히 연결할 때 ‘배정 전 공개 설명’으로 표시합니다. 이는 공개 설명의 연결 근거이며 서버의 실제 변경 원인을 증명하지 않습니다. 첫 배정 이후 모델 변경에는 옛 이유를 재사용하지 않습니다. 후속 재배정 이유는 명시 announce를 사용하세요. 이유가 없거나 연결이 맞지 않으면 ‘확인 불가’입니다. 시간상 가까운 문장을 추정해서 붙이거나 비공개 추론을 추출하지 않습니다. 최근 공개 설명은 파일별 12,000자, 연결 대기는 파일별 16개 호출, 연결 완료 이유는 전체 128개까지만 로컬 상태에 보관합니다.

자식 파일의 첫 session_meta를 보존하고 부모 메타로 바꾸지 않습니다. 자식의 task_started, 해당 thread_settings_applied 또는 token_usage_record로 확인된 실제 턴만 사용합니다. 오래되거나 다른 구조의 로그는 자식 변경을 놓칠 수 있으며 추정으로 부모 기록을 자식 실행에 더하지 않습니다.

물리적 LF 단위로 엄격 UTF-8을 읽고 미완성 마지막 레코드는 기다립니다. 파일 교체·잘림은 재검사하며 같은 최종 모델 상태는 재알림하지 않습니다. 잘못된 중간 레코드는 `work/diagnostics.jsonl`에 위치와 오류를 남깁니다. 알림 이력은 `work/history.jsonl`, 상태는 `work/state.json`, 실행 상태는 `work/heartbeat.json`입니다. 이력·진단은 각 2 MiB 초과 때 이전 파일 한 개를 보존하며 순환합니다. 무제한 이력 보관이 아닙니다.

탐색은 최신 디렉터리 우선 최대 4,096개 파일입니다. 한 주기 파일당 512 KiB, 전체 8 MiB를 읽은 뒤 다음 파일부터 이어갑니다. 완전한 레코드 경계를 지키기 위해 마지막 읽기는 레코드 상한인 2 MiB까지 예산을 초과할 수 있습니다. 2 MiB를 넘는 한 레코드는 LF까지 건너뛰며 진단에 기록합니다. 큰 과거 파일의 기준선은 여러 주기에 걸쳐 처리되므로 그 파일에 새로 붙은 변경의 감지가 지연될 수 있습니다. 대기 알림은 256개까지 보관하며 꽉 차면 읽기를 멈추고 매 주기 최대 16개를 전송합니다. 상태 파일 16 MiB 초과/손상 시 자동 초기화하지 않고 중단합니다. API 실패나 OS의 알림 비활성 상태는 큐를 보존하여 다음 주기에 재시도합니다. 전송 성공 직후 상태 저장 전 강제 종료되면 동일 알림이 재전송될 수 있습니다. 정확히 한 번의 화면 수신을 보장하지 않습니다. 일반 종료와 재시작은 상태로 중복을 방지합니다. 최근 8,192개 timestamp 포함 관측의 해시를 보존하여 회전 로그 복제를 제외하며, 이 범위보다 오래되거나 timestamp 없는 복제 기록은 다시 알림될 수 있습니다.

부모 조사에서 로그인 계정의 ChatGPT 알림 설정 Codex=푸시가 이미 켜져 있음이 관측되었으며 이 프로그램이 설정을 변경하지 않았습니다. 아이폰 ChatGPT 임의 모델 변경 푸시 API는 확인되지 않아 구현하지 않았습니다. Windows 성공을 모바일 수신으로 표시하지 않습니다.

## 검사

```powershell
& 'USER_HOME\.cache\codex-runtimes\codex-primary-runtime\dependencies\python\python.exe' -B -X utf8 -m unittest discover -s tests -v
& 'USER_HOME\.cache\codex-runtimes\codex-primary-runtime\dependencies\python\python.exe' -B -X utf8 tools/check_sources.py
```

실제 Windows 전송은 설치 후 `test-toast`와 Windows 표시 이벤트로 별도 확인합니다. 2026-10-21 06:26:06 한국 시각의 실제 시험은 종료 코드 0, `BalloonTipShown` 확인이었으며 사용자의 화면 수신과 알림 센터 저장은 미확인입니다. 모바일 ChatGPT 수신을 확인한 결과도 아닙니다. 자동 테스트는 임시 세션 파일과 주입한 전송 함수를 사용하며 화면 수신 검사가 아닙니다.

수리 5의 첫 전체 22개 검사에서는 기존 `test_partial_utf8_and_lf` 한 개가 임시 상태 파일 교체의 `WinError 5`로 실패했습니다. 다른 21개는 통과했습니다. 별도 cwd·TEMP의 해당 단일 검사에서는 재현되지 않았고 최초 실패 당시 잠금 소유자와 원인은 미확정입니다. 감지 코드는 이 오류를 이유로 추측 수정하지 않았으며 실패 원문은 `work/수리5-전체검사.json`에 보존합니다. 후속 최종 검사 결과는 별도 기록으로 구분합니다.
