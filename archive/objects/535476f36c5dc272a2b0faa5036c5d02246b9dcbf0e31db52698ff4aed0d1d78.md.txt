# 21차 원소별 입체 형태와 하단 도크·실제 잔량 막대

2026-10-26 사용자 직접 선택: 20차 시안 1번 하단 도크. 이전 원소31종은 같은 메시여서 거부하셨으며 각 원소마다 형태·색이 눈에 띄게 달라야 합니다. 최신 추가 요청은 실제 잔량이 정확한 막대로 보이도록 모든 세부를 확인하는 것입니다.

## 확인된 원인

19차 visuals.py는 원소 번호·기호·이름을 움직이는 링 안에 그립니다. 색을 바꾸는 element_visuals.py는 원본 메시를 그대로 재사용합니다. app.py는 실제 remaining/100을 usage_fraction으로 전달하지만 draw_orbit는 fraction 인자를 사용하지 않고 배경과 숫자만 그립니다. 따라서 막대 채움이 없었습니다.

## 변경과 성공 기준

- 투명 148×148 정사각형, 원소마다 다른 실제 3D 중심 메시·링 장식·색을 제작합니다. 세 링은 독립 축·속도의 18초 반복을 유지합니다.
- 링 아래 별도 도크에 번호·기호·이름을 두고 그 아래 잔량 트랙과 비례 채움을 둡니다. 글자와 움직이는 링의 최대 영역이 겹치지 않아야 합니다.
- fresh 잔량은 실제 조회값을 같은 숫자·막대에 연결합니다. 0/3/25/50/100%의 폭을 확인하며 작은 수치를 임의 최소 폭으로 부풀리지 않습니다. 미확인은 채우지 않고 지연은 지연으로 표시합니다.
- 팔레트와 기하는 원소의 용도·성질에서 얻은 디자인 영감이며 실제 전자궤도·고유 물리색으로 주장하지 않습니다. 31개는 번호·텍스트를 가린 실제 메시 형상도 구분되어야 합니다.
- 원소 날짜 규칙, KST 자정 갱신, SUIT 글꼴, 기존 감지·한도 조회·MD 보존을 유지합니다. 원본 atom3d 자산과 핵심 모듈은 보존합니다.
- 전체 회귀30초·소스15초·총45초와 자원 상한을 유지하고 별도 verifier가 검토합니다. 배포는 단일EXE·설치본으로 만들고 실행을 교체합니다.

## 역할과 증거

부모는 설계·배포·지침/런타임 기록을 소유합니다. Astra는 실제 31종 기하·제작 도구·재생 자산을, build는 도크·막대와 UI 연결을 맡습니다. verifier는 제품 수정 없이 요구사항·자산·기능을 대조합니다. 19차와 20차는 보존합니다. 같은 task의 누적은 repair61/input40에서 이어갑니다. 이번 준비의 assessment 필드 오류와 원문은 evidence에 보존했습니다.
