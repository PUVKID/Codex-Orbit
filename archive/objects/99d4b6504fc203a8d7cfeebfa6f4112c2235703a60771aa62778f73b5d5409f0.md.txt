# 캐릭터 창 인식과 실제 클릭 검증 계획

사용자 요청: 2026-10-25, 투명 배경·입체 회전·드래그를 유지하면서 화면 제어 도구가 캐릭터를 인식하게 수정하고 직접 클릭하여 상세창이 열리는 실제 화면을 보여 드립니다. 추가 디자인 승인 대신 실제 수정을 하라는 기존 지시를 따릅니다. 이전 6차는 보존합니다.

## 설계와 확인된 근거

6차 실제 Sky 목록에는 일반 Details 창만 있으며 부모 없는 Qt.Tool 캐릭터는 없습니다. 원본 6차에는 직접 캐릭터 클릭 증거가 없습니다. 창 종류 차이가 원인이라는 가설을 단일 변경으로 검증합니다. Qt 공식 문서는 Windows 투명 창에 WA_TranslucentBackground와 FramelessWindowHint가 필요하다고 설명하며 Tool을 필수로 요구하지 않습니다: https://doc.qt.io/qt-6/qwidget.html#creating-translucent-windows .

선택한 방법은 캐릭터를 일반 최상위 Qt.Window로 등록하고 투명/프레임 없음/항상 위/148 정사각형/기존 렌더·마우스 처리를 유지하는 것입니다. 창 접근성 이름과 설명은 실제 캐릭터 조작을 설명하도록 제공합니다. 일반 창의 작업 표시줄·Alt+Tab 노출 가능성은 수용 가능한 호환 영향으로 부모가 판단하며 실제 결과를 보고합니다. 불투명 감싸기 창은 외형을 해치고, 보이지 않는 대리 버튼은 직접 캐릭터 클릭이 아니므로 사용하지 않습니다. OS 입력 우회·임의 핸들·Codex 내부 변경을 하지 않습니다.

## 실행 계획

writing-plans 및 test-driven-development 스킬을 적용합니다. 구현자는 src/app.py, tests/test_orbit_window.py와 필요한 사용 안내만 소유하며 부모는 빌드·배포 도구, 문서·증거·상태를 소유합니다. verifier는 소스를 수정하지 않습니다. 실제 root는 이 7차이며 .git은 없습니다. 중앙 검사의 기존 30초/15초/총45초와 모든 기존 assert는 유지합니다. 같은 task orbit-monochrome-motion의 기존 repair7/input6을 복사하여 계속 누적합니다.

- [ ] 캐릭터가 일반 최상위 창이고 접근성 이름이 제공되는 관련 검사를 먼저 실패시키고 원문을 보존합니다.
- [ ] 창 종류와 접근성만 최소 수정하고 관련 검사·전체 회귀·소스 정확성을 실행합니다. 기존 투명 알파/모션 차이/드래그·클릭 구분 검사도 유지합니다.
- [ ] 실제 Windows에서 수정 앱의 창이 공식 Sky inventory에 나타나는지 확인합니다. 실패 시 원문을 보존하고 가설을 재판단합니다. 인식만으로 클릭 성공을 주장하지 않습니다.
- [ ] 단일 EXE·설치본·소스 ZIP을 새 7차에서 빌드합니다. 이전 사용자 기록과 설정은 별도 복사하고 6차 파일을 수정하지 않습니다.
- [ ] 최종 EXE를 상세창 자동 열기 없이 실행하고 캐릭터 실제 캡처 두 프레임으로 회전 지속을 확인합니다. Sky가 반환한 캐릭터를 직접 클릭한 뒤 Details 창이 새로 생기는 화면을 저장합니다. 보이지 않는 창이나 CLI 상세창 열기로 대신하지 않습니다.
- [ ] 독립 verifier Sol/high가 동결 소스와 요구/직접 실행 결과를 대조하고 중앙 검사를 실행합니다. 부모가 실제 child ID를 등록하며 최종 소스 변경 뒤 새 등록이 필요합니다.

## 검토 초점

투명 구석과 원형 외형 유지, 두 프레임 모션 차이, 드래그가 클릭으로 오인되지 않음, 상세창 숨김 뒤 다시 열림, 단일 실행 인스턴스와 원본 기록 보존을 확인합니다. 공개 모델 이유와 실제 계정 비율을 바꾸거나 새 모델 전환을 꾸미지 않습니다.
