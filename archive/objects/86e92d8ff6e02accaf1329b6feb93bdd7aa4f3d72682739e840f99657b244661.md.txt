# 모델·추론 선택 순간 알림

목표: 모든 로컬 Codex 채팅에서 모델 또는 추론 강도를 바꿨을 때 다음 메시지 실행을 기다리지 않고 정확한 채팅에 알림을 표시합니다. 이전6차 배포와 미배포7차를 보존하고, 8차는6차의 검증된 소스를 바탕으로 합니다. 캐릭터 외형·창 종류·모션은 이번 변경 대상이 아닙니다.

## 확인된 원인과 설계

설치 CLI0.163.0-alpha.10.2의 공식 생성 스키마는 thread/settings/update와 thread/settings/updated를 제공합니다. 설치 앱의 applyThreadSettings는 threadId와 model/effort를 이 요청으로 전달합니다. 실제 로컬 JSONL에는 event_msg.payload.type=thread_settings_applied, payload.thread_id, payload.thread_settings.model 및 reasoning_effort가 함께 있습니다. 현재 채팅에서21건을 관측했고 최근 설정 이벤트는 다음turn_context보다 먼저 있습니다. 단, 그 두 값은 동일하여 사용자 무전송 선택 변경의 인과·지연은 별도 실제 시험이 필요합니다.

기존 src/notifier.py Watcher.record는 설정 이벤트에서 owner_active만 갱신하고 모델·추론을 비교하지 않습니다. turn_context만 비교하므로 다음 실행을 기다립니다. 이 정확한 native 설정 이벤트를 처리하는 최소 수정이 선택입니다. 최근 전체 모델 값만 읽는 방법은 채팅ID를 확정할 수 없고, 별도stdio app-server를 띄우는 방법은 desktop 이벤트 공유가 확인되지 않았으므로 사용하지 않습니다. DB·인증·Codex 바이너리·UI를 수정하지 않습니다.

설정 변경은 ‘선택 설정 변경’이라는 근거로 표시하며 서버 실행 모델이나 사용자 변경 이유를 증명한 것처럼 쓰지 않습니다. 동일 선택값·후속 동일turn_context는 중복 알림을 만들지 않습니다. 실제 실행이 선택값과 다르면 기존 실행 관측 경로를 유지합니다. 일반/자식/여러날짜·프로젝트를 같은 세션 루트에서 감시하며 복제된 부모 설정 기록은 제외합니다.

## 구현과 검증 계획

systematic-debugging, brainstorming, writing-plans, test-driven-development를 적용합니다. 사용자께서 설명 대신 직접 구현을 요청하셨으므로 추가 설계 승인 질문은 반복하지 않습니다. 실제 선택 검증만 Codex UI 자동조작 금지에 따라 사용자 조작 한 번이 필요합니다. 이미 읽기 전용 관측기가 준비되어 있습니다.

- [ ] src/notifier.py의 설정 이벤트 처리에 대해 실행없는모델만/추론만/동시변경, 동일값반복, 후속turn중복, 원본시각과 정확ID, 잘못된필드·부모복제제외 검사를 먼저 실패시킵니다.
- [ ] 기존 state2의 감시 위치·기준선을 보존하여 새기능으로 이전할 때 이미 소비한 과거 설정은 새 알림으로 내지 않고 기존offset 이후 변경은 잃지 않는 회귀를 작성합니다. 필요 시 원본 상태 백업과 명시적인 한번의 기준선 재생을 사용하며 오류를 초기화해서 숨기지 않습니다.

- [ ] 기존 검사 명세30초/15초/총45초와 assert를 약화하지 않고 전체 회귀·엄격UTF8·구문을 실행합니다. 파일회전·부분LF·중단중새변경·재시작중복·오류기록 경계도 보존합니다.
