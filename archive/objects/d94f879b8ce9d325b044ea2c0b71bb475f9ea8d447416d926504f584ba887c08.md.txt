# Codex Orbit 전면 재디자인 명세와 실행 계획

사용자는 기존 화면의 부분 수정이 아닌 완전히 새롭고 깔끔한 디자인과 모션 그래픽을 요청했습니다. 2026-10-26 무료로 쓸 수 있는 설치 플러그인을 나누어 최대한 활용하도록 지시했습니다. 이전 자율 진행 요청도 유효하므로 시안 승인 질문을 반복하지 않습니다. 부모가 제안한 시안을 실행 기준으로 선택했으며 사용자 직접 승인으로 표현하지 않습니다.

## 도구와 비용 경계

Build Web Apps의 frontend-app-builder를 디자인·컴포넌트·타이포그래피 기준으로 사용합니다. 실제 시각 시안은 내장 imagegen으로 생성한 evidence/새디자인_시안.png이며 별도 설치 플러그인에서 생성했다고 말하지 않습니다. Computer Use는 실제 Windows 앱 검토에 사용합니다. Runway는 인증됐으나 Free/0크레딧/영상 모델 없음이 확인되어 생성·결제하지 않습니다. Game Studio는 게임용이므로 억지로 적용하지 않습니다. 외부 계정 연결·API 키·과금 요청은 하지 않습니다.

## 새 디자인

- 원형 HUD 눈금과 가는 튜브 장식을 걷어내고, 3개의 굵은 은색 리본형 짐벌을 만듭니다. 매끈한 금속 면, 밝은 가장자리와 어두운 측면, 원근·앞뒤 가림이 실제 시간에 따라 변합니다. 148×148 투명 배경·전체 정사각형 경계를 유지합니다. 중앙 숫자는 장식과 독립하여 가려지지 않습니다. 연속 회전과 하이라이트 이동, 잔량 진행 호의 움직임을 사용합니다. 임의 중간 수치를 실제 잔량으로 표시하지 않습니다.
- 앱은 무채색 흑연 바탕(#101010/#181818), 얇은 구분선, 넓은 여백을 사용합니다. 제목·큰 새 값·작은 이전 값·이유 순으로 위계를 분명히 합니다. 모든 글꼴은 내장 나눔고딕 Bold700입니다.
- 상세창 상단은 단정한 네비게이션, 이력은 왼쪽 최근 목록과 오른쪽 선택 상세로 구성합니다. '모델이 바뀌었습니다' 또는 '추론 강도가 바뀌었습니다'를 크게 표시합니다. 정확한 채팅 제목과 기존→새 모델·추론을 나눠 보여주고 원문 ID/근거는 접어 둡니다. 세로 공간 부족 시 스크롤로 접근 가능합니다.
- 알림은 채팅 제목, 무엇이 바뀌었는지, 기존→새 값 순서로 배치한 새 플로팅 패널입니다. 닫기 영역30px 이상, 각 항목 독립 표시·클릭 정확 ID·8개 상한을 유지합니다. 작은 움직임은 지연 없이 즉시 보이는 시작 상태에서 진행합니다.
- 사용 한도·내 지침·설정·도움말·파일 선택·메시지 등 앱 소유 표면 전체를 동일한 새 시스템으로 정리합니다. MD는 명시 적용·미리보기·백업·원복·동시 변경 거부를 유지합니다.
- 시안의 채팅/모델/85%/이유/날짜는 예시입니다. 실제 앱에는 현재 관측값만 연결하며 생성된 이유·가짜 기록·자동 모델 전환 설명을 넣지 않습니다. 모델의 정확 ID와 추론 원문은 유지합니다. 비공개 추론을 수집하지 않습니다.

## 구현 선택과 대안

기존 PySide6/QPainter 네이티브 앱을 유지하여 감시·MD·잔량을 연결합니다. 영상 재생 방식은 알파 경계·배포 용량·수치 상호작용 때문에 제외했습니다. 전면 WebView 전환도 감시/클릭 회귀와 배포 런타임 증가 때문에 이번에는 하지 않습니다. 따라서 frontend-app-builder의 브라우저 시안 검토와 별도로 실제 출하 UI는 Qt 렌더/실제 EXE로 비교합니다. 브라우저 결과만으로 네이티브 일치를 주장하지 않습니다.

## 책임과 순서

1. build는 src/app.py, src/theme.py, src/visuals.py, tools/generate_visual_assets.py, 관련 tests 및 README/사용법을 소유합니다. 감지/이유/core/usage/notifier는 이번 디자인 범위에서 수정하지 않습니다. 기존 모든 동작과 안전 경계를 보존합니다. 다른 작업자의 변경을 되돌리지 않습니다.
2. 부모는 docs/evidence/work 디자인 미리보기, 상태/실패 누적, 버전·패키징·배포·실행 교체를 소유합니다. 이전 차수와 운영 데이터는 보존합니다.
3. 구현 전 현재 화면과 새 시안을 직접 보고 요구 차이를 기록합니다. 새 구조·모션·작은 창·긴 제목·실제 숫자/미확인/지연에 필요한 검증을 추가하고 기존 전체 회귀를 실행합니다. 디자인 변경으로 더 이상 유효하지 않은 정적 모양 기대는 명세 근거를 남겨 교체하며 기능 기대값을 약화하지 않습니다.
4. 새 원본 시안과 실제 기본창·작은 창·이력·알림·잔량·MD·설정·도움말·대화상자, 서로 다른 시간의 링 프레임을 직접 비교합니다. 플러그인 시안도 납품 이미지 UI로 쓰지 않고 모든 컨트롤을 실제 기능으로 구현합니다.
5. 별도 verifier Sol/high가 최종 동결 소스와 요구를 대조하고 회귀/화면/실패 경로를 검사합니다. 중앙 검사30초/15초/총45초를 유지하고 새 등록·독립 영수증을 발급합니다. 이전10차 영수증은 새 완료 근거가 아닙니다.
6. 단일 EXE·설치형·소스ZIP·사용법을11차에서 빌드하고 실제 실행·설치·제거/MD보존을 확인합니다. 기존 앱의 경로와 PID를 확인한 뒤 이 앱만 교체하고 바탕화면 바로가기를 갱신합니다. 사용자 기록은 조작하지 않습니다.

## 검토 초점

- 740×540과 긴 한글 제목에서도 주요 값과 닫기/적용 버튼이 잘리지 않아야 합니다.
- 모션 프레임의 알파0/1:1/무채색/비동일 프레임, 중앙 숫자 불변, 시간 연속성을 확인합니다.
- 모델만·강도만·동시 변경, 후속 실행 중복 억제와 정확 ID 클릭이 유지되어야 합니다.
- 설정 재시작 예산과 비동기 종료, 조회 오류/이전 값 표시를 보존합니다.
- 기존 로그와 입력 보정18/수리21까지 이력을 보존합니다. 신규 실패는 원문을 먼저 기록하고 재판단합니다.
