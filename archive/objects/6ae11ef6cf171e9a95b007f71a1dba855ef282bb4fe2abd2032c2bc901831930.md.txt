# 멀리서도 구별되는 로고와 상태 표시

사용자는 작업 중 11차 실제 화면을 본 뒤 로고 등 모든 표시가 멀리서도 무엇인지 구별되게 디자인하라고 요청했습니다. 기존11차 소스·실행본·검증 준비 자료는 보존하고12차에서 이어갑니다. 같은 전면 디자인 작업이므로 orbit-monochrome-motion과 누적 수리25/입력19를 유지합니다. 11차는 중앙 최종 영수증을 아직 발급하지 않은 검토본입니다.

## 부모가 선택한 방향

- 바탕화면/작업표시줄/창/알림/설치 그림에 하나의 Codex Orbit 식별 마크를 사용합니다. 원칙은 굵은 O자 궤도와 비대칭의 위성 표식, 선명한 흑백 대비입니다. 16px에서 읽을 수 없는 세부 링·퍼센트·작은 글자는 정적 아이콘에서 제거합니다. 정사각형148의 실시간 캐릭터에는 기존 입체 리본 모션과 실제 잔량을 유지합니다.
- 정적16/24/32/48/64/128/256px에서 큰 덩어리·충분한 선 굵기·외곽 여백이 살아야 합니다. 작은 창 아이콘도 따로 확인합니다. 밝은 바탕과 어두운 바탕 모두 식별할 수 있도록 반전 경계가 있는 실루엣을 사용합니다.
- 상세창 헤더·알림에는 동일한 단순 마크를 실제 이미지/벡터 렌더로 넣고 충분한 크기로 표시합니다. 버튼/작은 상태점은 무슨 뜻인지 알 수 있는 한글 라벨과 함께 둡니다. 위젯 아래의 무의미한 작은 점은 '감시 중'/'확인 필요'/'새 변경' 등 실제 상태로 구분되는 대비 높은 표시로 대체합니다. 148×148을 벗어나거나 중앙 실제 잔량을 가리지 않습니다.
- 나눔고딕 Bold700, 흑백, 투명 배경, 새값 위계, 실제 기록과 잔량, 정확 ID 클릭, 독립 동시 알림과 MD안전 기능을 유지합니다. 표시를 명확하게 하는 수정이며 새 계정·권한·과금·외부 데이터 전송은 하지 않습니다.

## 도구와 책임

Build Web Apps의 기존 전면 시안·타이포그래피·아이콘 일관성 기준을 계속 적용합니다. 정적 아이콘은 현재 코드 자산을 기반으로 QPainter 벡터로 만들며 새 유료 이미지/영상 생성은 하지 않습니다. 내장 imagegen 시안은 이전11차 작업의 참고물이며 Runway 생성으로 주장하지 않습니다. Computer Use는 실제 Windows 표면 검토에 사용합니다.

build는 src/app.py/theme.py/visuals.py 및 필요 새 브랜드 렌더 모듈, tools/generate_visual_assets.py,관련 tests/README/사용법/생성아이콘·설치그림을 소유합니다. 감지·core/notifier/usage와 MD/설정/수명주기 로직은 수정하지 않습니다. 부모는 버전2.0.1·상태·배포·설치·실행 교체와 문서, 별도 verifier는 독립 검증을 담당합니다. 다른 사람 변경을 되돌리지 않습니다.

## 성공 조건과 검증

1. 실제16/24/32px 아이콘을 확대가 아닌 원래 크기와2배에서 보고 밝은/어두운 배경 모두 선명함을 확인합니다. ICO일곱해상도·1:1·투명모서리·무채색을 확인합니다.
2. 헤더/알림/위젯하단 상태를 각각 기본창/740창/320px 작업영역에서 확인합니다. 148외곽·중앙숫자 가독성·실제 state와 문구 일치·가려짐이 없어야 합니다.
3. 기존145회귀와 필요한 새 기준, UTF8/구문37+파일을 실행하며 기능30초/소스15초/총45초 명세를 유지합니다. 형식 기대만 새 명세 근거로 바꾸며 기능·수치·동시알림 기준을 약화하지 않습니다.
4. 별도 verifier가 최종 시각 결과와 독립 동작을 검사한 뒤 부모의 실제 ID/로컬 실행 근거 등록에 따라 새 최종 영수증을 발급합니다.
5. 새 단일 EXE/설치본/소스ZIP·사용법을12차에 빌드하고 실제 설치/제거·사용자MD보존·실제잔량·모션을 확인합니다.11차의 원본데이터를복사해12차로실행교체하고바탕화면바로가기도새경로로연결합니다.
