# 최초 중단 조사와 실제 모델 연속 알림

사용자 후속 요청: 최초 감시 정지 원인을 찾아 수리하고 실제 다른 작업자 모델을 연속 배정하여 누락·순서를 시연합니다. 4차 산출물과 실패를 보존하고 5차에서 같은 orbit-live-usage 작업을 이어갑니다. 4차 중앙 상태 원본을 복사하고 begin에서 기존 repair8/input2를 유지했습니다. 과거 영수증은 이전 소스용이며 5차 통과 근거로 쓰지 않습니다. 새 명령 입력 오류도 계속 누적합니다.

## 확인된 증거와 미확인 범위

- 과거3차 C데이터 heartbeat 마지막은17:32:29, 이후 새3차GUI56188 시작17:32:36입니다. C app.lock은이전60620으로남았습니다. 당시 process 환경·오류창 원문은 보존되지 않았습니다. 따라서 C환경을 새프로세스도 사용했는지나 시작실패/실행중중단 중 어느쪽인지 단정하지 않습니다.
- Application/WER/CrashDumps의 관련시간 CodexOrbit 충돌 근거가 발견되지 않았고 현재 제목캐시mtime17:03이며 정상입니다. 가상의캐시손상을 최초원인으로 꾸미지 않습니다.
- 실제4차 운영 diagnostics에19:54:19/19:54:42/20:01:59 KST state.json.tmp→state.json WinError5가 남아 있습니다. 단독 교체 실패는 재시도되나 오류 기록 쓰기까지 실패하면 외부 catch에서 스레드가 종료되는 코드 경로가 있습니다. Windows 삭제공유 없는 reader로 격리 재현하고 원본파일을 보존하며 수리합니다.
- 3차/4차 생성자에서 orbit.show가 감시 시작 준비보다 앞서 있어 시작 준비 예외 시 회전 위젯이 떠 있는 채 오류창 이벤트 루프에 남을 수 있습니다. 이는 재현 가능한 경로이며 당시 실제로 발생했다고 단정하지 않습니다. 감시 준비 전 정상 상태 표시와 원인 기록 소실을 막습니다.
- 5차 work/probe_order.py는 같은 poll의 source timestamp1/2/3인 파일을 넣었는데 역순 파일 열거로 실제알림3/2/1을 재현했습니다. 제어 fixture이며 실제모델교체와 구분합니다.

## 수리와 성공 조건

1. atomic_json은 원본을 삭제하거나 권한을 바꾸지 않습니다. 임시파일 충돌을 피하고 공유 위반은 제한된 재시도 후 명시 실패합니다. 완전한 기존 상태를 유지하고 실패 임시파일을 정리합니다. 오류 기록의 실패가 본 감시기를 종료시키지 않게 최초 오류와 기록 실패를 UI/상태에 명시하고, 잠금 해제 후 정상 감시와 알림이 회복돼야 합니다.
2. 필수 감시 준비가 실패하면 정상 회전 위젯만 남기는 시작 흐름을 막습니다. 준비 전 healthy 표시를 금지하며 시작/감시 실패는 민감한 대화 없이 PID·시각·단계·경로·오류로 추적할 수 있게 기록합니다. 상태 손상을 초기화해서 숨기거나 검증을 약화하지 않습니다.
3. 원본 turn_context 시각을 별도 보존하고 같은 전송 배치에서 원본 시각 순서로 대기를 정렬합니다. 원본 시각 누락·잘못된 시각은 추정하지 않고 안정적인 감지 순서를 유지합니다. 이미 전달한 과거 알림을 재정렬했다고 주장하지 않으며 지연 파일의 한계를 기록합니다.
4. 기존 잔량·MD·FIFO·정확 클릭·비동기 종료 검사와 신규 실패 경로를 실행합니다. 유효한 실제로그/이력을 조작하지 않습니다. 원본 기록과 시연·제어 입력을 구분합니다.
5. 새5차 단일EXE/설치본을 빌드하고 실제사용환경에 정상 교체합니다. 사용자에게 모델·강도·대상·선택 이유를 각 배정 직전 안내하고, 지원되는 새 작업자 교체 방식으로 Luna→Astra→Sol의 실제 별도 child를 순차 배정합니다. 같은child 모델변경 도구가 지원되지 않는 한계를 우회하지 않습니다. native turn_context→감지→대기→표시 단계별 실제ID/순서를 대조합니다. 사용자 확인이 없는 클릭을 했다고 말하지 않습니다.
6. 구현자와 다른 verifier Sol/high가 최종 소스를 검사하고 중앙 영수증을 발급합니다. 모델 시연에 쓰는 child도 실제 유용한 읽기 전용 대조 업무를 맡기고 추가 child를 만들지 않습니다.

현재 조사는 deep Sol/xhigh, 부모는 분류/배포/증거/라우팅을 소유합니다. 구현 배정 전에는 제품 수정을 하지 않습니다. 이후 구현자는 명시된 관련 파일만 수정하며 이전차수·전역설정·실사용원본을 수정하지 않습니다. 글꼴은 나눔고딕Bold700, 디자인은 기존 다크테크를 유지합니다.
