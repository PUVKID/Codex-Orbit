2차 public_reason은 바로 직전 공개 commentary와 spawn call_id/결과가 같은 감시 주기에 준비됐을 때 첫 배정에만 이유를 붙입니다. 부모 기록이 뒤늦게 읽히거나 다른 도구가 사이에 있거나 native function_call 이름이 다르면 실제 이유가 공개돼 있어도 누락될 수 있습니다. 각 누락의 실제 로그를 확인한 뒤 최소 범위로 수정합니다.

기존 child의 모델을 app 도구로 변경하는 실제 요청은 multi-agent v2 sub-agents direct app-server input 제한으로 거부됐습니다. 실제 변경으로 기록하지 않습니다. 지원되는 새 모델 child 배정/교체는 같은 child 내부의 모델변경과 구분하여 표시합니다. Codex DB·인증·설정·훅을 수정해 우회하지 않습니다.

## 구현과 검증

1. Astra 작업자가 src/, tests/, assets/사용법.md와 기본_지침.md, tools/check_sources.py를 소유합니다. 부모는 packaging/tools/build_distribution.py/installer.iss, docs, 증거, 라우팅 상태를 소유합니다. 다른 변경을 되돌리거나 추가 작업자를 생성하지 않습니다.
2. 제목은 확인된 로컬 source와 provenance/확인시각을 보존합니다. 자식은 부모의 정확한 채팅 제목과 자식 역할/작업 이름을 구분합니다. 명시적으로 앱에서 확인해 저장한 title-cache도 지원하며 오래된 값을 현재 조회라고 속이지 않습니다. 제목을 임의 축약·개명하거나 첫 프롬프트를 제목으로 가장하지 않습니다.
3. 공개 이유는 정확한 요청/콜ID/대상 ID/경로와 모델 전후에 연결합니다. 추정·비공개 reasoning 수집 금지. 누락 시 상세 증거를 보존합니다. 늦은 이유/제목 수집은 기존 이력을 새 알림 폭탄 없이 보강할 수 있어야 합니다.
4. 다크테크: 거의 검은 바탕, 얇은 시안 테두리/상태점, 읽기 쉬운 나눔고딕 Bold. 기본 화면은 채팅 제목·작업·전후 모델·추론 강도·한국시각·핵심 이유를 짧게 표시합니다. ID/근거/긴 원문은 접을 수 있는 상세 영역으로 보존합니다. 알림 말풍선에도 제목·전후·이유를 포함하며 클릭은 그 알림 항목을 엽니다. 사용자 확인을 위해 짧은 자동닫힘을 늘리고 알림을 이력에서 다시 볼 수 있습니다.
5. 이전 MD 백업/충돌/원복 안전장치와 투명 회전·드래그는 유지합니다. 변경을 재현하는 테스트를 먼저 작성하고 기존 회귀를 포함해 검증합니다.
6. 부모는 EXE와 설치형을 재빌드하고 기존2차 위젯을 정상 종료 후 새3차 실행본으로 교체합니다. 실사용 데이터는 보존합니다. 실제 새Astra child 관측과 명시 교체 이유를 연결해 사용자에게 클릭할 알림을 띄웁니다. 독립 verifier가 실제 로그·이력·클릭 상세와 배포본을 검사합니다.
