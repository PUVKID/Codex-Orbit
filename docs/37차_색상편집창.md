# 37차 색상 편집창의 표시 정지 수정

<!-- user-levels:start -->
[LEVEL 1](읽기안내/레벨1.md) · [LEVEL 2](읽기안내/레벨2.md) · [LEVEL 3](읽기안내/레벨3.md) · [LEVEL 4](읽기안내/레벨4.md) · [LEVEL 5](읽기안내/레벨5.md)
<!-- user-levels:end -->

**색상 꾸미기 창을 표시할 때 멈추는 기존 결함**을 37차에서 수정했습니다. 색상과 조명 기능을 없애지 않고, 미리보기 카드의 조명을 직접 그리는 방식으로 바꿨습니다.

| 구분 | 확인된 내용 | 범위와 한계 |
| --- | --- | --- |
| 기존 증상 | 기본 조명 강도에서 `AppearanceDialog` 생성은 끝나지만 `dialog.show()`가 반환하지 않음 | 35차에도 있던 표시 경로이며 37차에서 원인을 분리 |
| 원인 분리 | 합성 프로세스에서 카드의 `QGraphicsDropShadowEffect`만 제거하자 표시·화면 이벤트 처리·닫기가 반환 | **오프스크린의 카드 그래픽 효과 표시 경로**까지 좁혔으며 Qt 내부의 세부 원인은 미확정 |
| 수정 | `AmbientPreviewCard`가 `QPainter`로 카드 안쪽에 둥근 알파 테두리 7개를 그림 | 자식 위젯 전체를 그래픽 효과로 합성하지 않음 |
| 조명 연결 | 사용자 원색 `accent_raw`와 조명 강도 0~100을 사용 | 강도 0이면 추가 조명을 그리지 않음 |
| 읽기와 배치 | 카드 안쪽 클립과 기존 레이아웃 여백에서 조명을 그림 | 본문 중앙 픽셀·카드와 창의 크기·위치를 검사 |
| 기존 기능 | 원색·대비 팔레트·프리셋·한영·굵은 글꼴·적용·취소·실패 시 원본 유지 | 기존 기대값을 약화하지 않음 |

미리보기만 바뀌며 앱 전체의 테마·설정·날짜 조형은 이 수정에서 변경하지 않습니다. 라이트·다크 선택과 조명 강도는 기존 미리보기 동작을 유지합니다.

## 필요한 부분만 확인한 결과

설정 5개와 팔레트 4개의 기존 통과 근거는 재사용했습니다. 이번에는 **기존 대화상자 7개와 신규 이미지 회귀 1개**만 한 번 실행했습니다.

검사 프로세스는 앱과 동일하게 `QApplication`을 만들고 번들 글꼴 `app_font()`를 적용했습니다.  
`QT_QPA_PLATFORM=windows`를 지정했으며 실행 중 `app.platformName()`도 `windows`로 확인했습니다.  
Python은 프로젝트의 기존 실행 환경을 사용했고 인자는 `-B -X utf8 -u -c`였습니다.  
실행 위치는 37차 루트이며 검사 대상은 `test_appearance35.DialogTests`입니다.

| 검사 | 실제 확인 |
| --- | --- |
| 표시와 합성 저장 실패 | 이전에 멈췄던 표시 경로를 지나 실패 문구를 보여 주고 원본 설정과 열린 창 유지 |
| 취소와 미리보기 | 적용 콜백을 호출하지 않고 앱 전역 스타일·팔레트 유지 |
| 적용과 재열기 | 정규화된 독립 사본을 적용하고 같은 설정으로 다시 읽음 |
| 잘못된 HEX | 입력 오류 설명과 적용 차단 유지 |
| 프리셋·복원·강도 0 | 초안만 변경하며 강도 0에서 그래픽 효과 없음 |
| 색 선택 취소 | Qt 색 선택 호출의 취소 시 기존 값 유지; 색 선택 결과는 모의 입력 |
| 한영과 글꼴 배율 | 13·20px에서 한영 각각 검사하고 굵기·가로 스크롤 없음·하단 버튼 접근성의 기존 단언 유지 |
| 실제 이미지 회귀 | 카드 캡처 `QImage`를 비교하여 발광 0/100의 픽셀 차이, 본문 중앙 픽셀 유지, 동일 배치, 다시 0일 때 원래 이미지 복원 확인 |

**8개 통과**, 자식과 실행 래퍼의 종료 코드 0입니다.  
unittest 측정은 39.921초이며 초기화와 프로세스 회수를 포함한 전체 시간은 55.266초입니다.  
172초 제한 안에서 정상 종료했으며 강제 종료하지 않았습니다.

이 결과는 실제 Windows Qt 합성 창과 `QTest` 조작의 결과입니다.  
CUA를 통한 사람 방식의 마우스 조작, 최종 배포 EXE·설치본·전체 회귀를 확인한 결과로 확대하지 않습니다.  
앞선 오프스크린 시간 초과와 이후 통과는 서로 다른 실행으로 구분하며 실패 이력은 보존합니다.  
빌드·설치·공개 반영은 부모 통합 작업에서 다룹니다.

현재 배포 파일과 GUI 연결 관측은 [37차 최소 검사](37차_최소검사.md)에 기록합니다. 각 모듈의 확인 결과를 전체 회귀·실제 업데이트 통과로 확대하지 않습니다.
