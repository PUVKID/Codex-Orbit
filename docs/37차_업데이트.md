이 문서는 **37차 업데이트 모듈**의 변경만 설명합니다. 부모 종료 대기, 공식 저장소·다운로드 주소 제한, SHA-256 검증, 시작 검사 실패 시 이전 EXE 복구는 기존 기능입니다.

| 항목 | 37차 동작 | 범위와 조건 |
| --- | --- | --- |
| 버전 | 업데이트 창의 현재 버전은 **3.7.0** | 앱·설치 파일 버전은 별도 통합 범위 |
| 공식 페이지 | 사용자 버튼으로 공식 릴리스 목록 열기 | 고정 `https://github.com/PUVKID/Codex-Orbit/releases` 주소만 QDesktopServices에 전달 |
| 다운로드 크기 | 다운로드 전 MB 표시 | 1 MB = 1,048,576 bytes, 소수 둘째 자리 반올림 표시 |
| 공간 확인 | 준비 폴더의 실제 볼륨에서 다운로드 전 검사 | **자산 크기 × 3 + 64 MB**보다 여유 공간이 작으면 다운로드 요청을 시작하지 않음 |
| 검증값 복사 | 다운로드·크기·SHA-256·EXE 형식 검증 후 복사 버튼 표시 | 서버 메타데이터만 확인한 상태에서는 표시하지 않음 |
| 설치 직전 안내 | 기존 EXE 1개 백업 예상과 개인 설정·MD 유지 안내 | 개인 설정 자체를 새로 복사·초기화하는 기능이 아님 |
| 단계 | 릴리스 확인 → 다운로드 → 검증 → 설치 준비 | 측정하지 않은 진행률을 표시하지 않음 |
| 오류 | 짧은 대응 안내와 원문 펼치기 | 원문은 읽기 전용 일반 텍스트, 링크나 HTML로 실행하지 않음 |
| 최근 결과 | 사용자 데이터 폴더의 `update-result.json` | 허용된 상태·UTC 시각·버전·오류 코드만 원자 교체로 기록 |
| 닫기 | 결과 창을 닫아도 개인 설정 유지 | 작업 중 닫기·Esc를 제한하며, 창 삭제 후 스레드 콜백은 유효한 bridge에만 전달 |

`SafeUpdater.stage(release, progress=None)`는 기존 호출을 유지하며 선택적으로 `download`, `verify` 단계를 전달합니다.

`read_update_result(data_directory)`는 허용된 필드만 가진 사전 또는 빈 사전을 반환합니다. 최대 16 KiB만 허용하며, 손상된 JSON·비정상 버전·시각·오류 코드·추가 필드·심볼릭 링크·Windows 재분석 지점을 거부합니다. 쓰기 경로도 사용자 데이터 폴더의 입력 경로를 먼저 해석해 없애지 않고 검사합니다. 이 로컬 검사는 같은 권한의 악의적 동시 경로 교체까지 막는 서버 보안 경계가 아닙니다.

| 결과 상태 | 의미 | 기록되는 오류 |
| --- | --- | --- |
| `updated` | 새 EXE 시작 검사와 재시작 확인 성공 | 없음 |
| `rolled_back` | 이전 EXE 복원 후 재시작 확인 성공 | `apply_failed`, `smoke_failed`, `restart_failed` 중 해당 단계 |
| `failed` | 교체 전 실패, 복원 실패 또는 이전 EXE 재시작 확인 실패 | 위 코드 또는 `rollback_failed`, `rollback_restart_failed` |

파일 복원만 성공하고 이전 EXE 재시작이 실패한 경우를 복구 성공이라고 표시하지 않습니다.

기록에는 개인 경로·자격 증명·예외 원문을 넣지 않습니다. 결과 기록 실패는 EXE 복구를 막지 않으며 원래 업데이트 예외를 대체하지 않습니다. 기존 개인 설정·MD 파일은 이 기능에서 수정하지 않습니다.

## 이번 확인 범위

| 확인 | 결과 |
| --- | --- |
| 다운로드 전 공간 부족과 임계값·준비 볼륨·단계 순서 | 합성 검사 통과 |
| 결과 필드 제한·16 KiB 제한·손상 입력 | 합성 검사 통과 |
| 결과 경로 재분석 지점 거부 | 합성 속성 검사 통과 |
| 결과 기록 실패 중 복구 및 원래 예외 보존 | 합성 검사 통과 |
| 이전 EXE 복구 후 시작 성공 | 합성 검사 통과 |
| 이전 EXE 복구 후 시작 실패 구분 | 합성 검사 통과 |
| 버전·고정 URL·일반 텍스트·복사·닫기·재열기 | 별도 Qt 합성 검사는 패널 생성 정지로 미완료, 부모 통합 확인 범위 |

검사 명령은 프로젝트 루트에서 지정 Python의 `-B -X utf8 -S`로 `test_update37.Update37Tests`의 비 GUI 6개 메서드만 실행했습니다. **6개 통과**, 종료 코드 0, unittest 측정 0.389초입니다. 쓰기 경로의 링크 원형 보존 수리 뒤에는 해당 재분석 지점 검사만 1개 실행해 통과했습니다(0.083초, 종료 코드 0). 기존 전체 회귀 검사는 반복하지 않았습니다.

실제 HTTP 다운로드, 실제 사용자 설치·업데이트, 재부팅, 실제 배포 EXE, 직접 화면 조작은 이 모듈 작업에서 실행하지 않았습니다. 라이트·다크 테마는 부모 창의 기존 테마를 상속하며 별도 전역 스타일을 추가하지 않습니다.

## 통합 검사에서 발견한 기존 닫기 결함 수정

부모의 37차 GUI 통합 검사에서 창을 닫을 때 `UpdateDialog.done() missing 1 required positional argument: error`가 발생했습니다. 35차부터 존재했던 결과 처리 메서드 `done(value, error)`가 Qt의 `QDialog.done(result: int)`를 덮어쓴 기존 결함을 이번 검사에서 확인한 것입니다.

37차에서는 결과 처리 메서드를 `handle_result(value, error)`로 바꾸고 결과 신호 연결과 합성 검사의 직접 호출을 함께 수정했습니다. 문법과 이름 연결만 확인했으며, 닫기 동작의 재확인은 부모 통합 검사 범위입니다. 기존 비 GUI 6개 검사는 반복하지 않았습니다.

현재 배포 파일과 GUI 연결 관측은 [37차 최소 검사](37차_최소검사.md)에 기록합니다. 각 모듈의 확인 결과를 전체 회귀·실제 업데이트 통과로 확대하지 않습니다.
