# 34차 GPU 프로세스 격리

날짜별 조형의 실제 GPU 작업은 전용 자 식 프로세스가 실행합니다. 부모의 CalendarMotion과 감독 QThread는 기존 날짜·국가·도시·모션 시계·정지·가시성·최신 프레임 통지를 유지합니다. 96×96 픽셀 타깃, 최근접 확대, 3840×2160 원본 렌더 설정과 기존 메시·재질은 바꾸지 않았습니다.

## 실행과 소유권

단일 실행 파일의 orbit_entry가 일반 앱과 내부 GPU 요청을 무거운 GUI import 전에 분기합니다.

소스 실행은 현재 Python과 같은 폴더에 있는 pythonw.exe를 명시 선택하고 절대 경로의 entry를 사용합니다.

같은 실행 환경의 pythonw.exe가 없으면 명시 오류로 중단하며 콘솔 Python으로 돌아가지 않습니다. frozen 실행은 기존과 같이 동일한 windowed EXE와 내부 역할 인자를 그대로 재사용합니다.

자식은 QApplication·위젯·계정 조회·날씨 네트워크·개인 설정 저장을 시작하지 않습니다.

손상된 내부 요청은 일반 GUI로 떨어지지 않습니다.

Windows CreateProcessW로 초기 스레드를 정지 상태로 만든 뒤, 부모만 소유하는 kill-on-close Job에 할당하고 재개합니다. breakaway와 핸들 상속은 허용하지 않습니다.

전역 프로세스 이름 검색이나 다른 앱 종료를 사용하지 않습니다.

이전 콘솔 소스 실행에서는 venv Python·base Python·conhost 세 프로세스를 관측했습니다.

현재 pythonw 소스 실행 한 번에서는 같은 venv의 GUI 실행기와 base GUI 실행 기 두 프로세스의 실제 경로를 확인했으며, 정확한 Job 구성 원 핸들을 계속 수집합니다.

종료 성공은 Job ActiveProcesses =0, 누적 구성원 수와 확보핸 들 수 일치, 각 핸들의 실제 signaled, 감독 QThread 완료, 공유 자원 회수를 함께 확인합니다.

## 유한 IPC와 자료 갱신

현재 사용자 SID만 허용하는 DACL과 임의 세대 nonce를 가진 Local 매핑·이벤트·뮤텍스를 사용합니다.

요청 슬롯은 65,536바이트, 응답 JSON은 16,384바이트, RGBA8888 영상 슬롯은 최대 2160×2160×4 바이트입니다.

헤더를 포함한 공유 매핑은 18,744,448바이트 한 개입니다.

실제 전달 크기만 복사하며, 세대·요청/응답 ID·JSON 길이·영상 폭/높이·stride·픽셀 형식·날짜/지역 문맥을 검증합니다. pickle과 무제한 Queue/Pipe를 쓰지 않습니다.

GPU native 호출 동안 mutex를 보유하지 않습니다. stop 이벤트는 mutex와 독립적입니다.

부모의 짧은 수명 잠금은 stop 신호와 최종 IPC 핸들 회수만 직렬화하며, GPU 호출과 프로세스 종료 대기는 이 잠 금 밖에서 수행합니다. abandoned mutex, 잘린 헤더, 이전 세대, 잘못된 크기·상태는 정상 프레임으로 받지 않습니다.

초기화는 ready 응답, 달력·관측소 렌더는 frame 응답만 허용하며 busy 응답도 기존 5초 응답 기한을 넘어 대기하지 않습니다.

부모 최신 QImage 한 개와 정적 fallback 한 개의 기존 계약을 유지하고, 공유 영상 슬롯 및 전송 중 유한 바이트 복사 본은 별도 메모리로 구분합니다. 부모 QImage는 매핑을 외부 저장소로 계속 참조하지 않습니다. 자식의 렌더 결과를 복사한 뒤에만 최신 프레임을 교체합니다.

도시 자료는 부모가 선택한 기존 읽기 전용 캐시 경로와 revision을 전달합니다.

자식은 기존 configure_city_cache와 자료 검증 경로를 사용하고, 실제 revision을 부모 값과 대조합니다.

경로 또는 revision 변경 시 날짜·국가 자료 캐시를 비웁니다.

자식이 사용자 자료를 다운로드하거나 새 설정을 저장하지 않습니다.

## 종료와 한계

기존 2초 종료 예산 하나를 유지합니다.

정상 종료 요청 후 최대 0.75초를 기다리며 필요한 경우 소유 Job만 강제 종료하고 남은 같은 예산 안에서 실제 회수를 확인합니다. 0.75초는 소스 Python 후손의 정상 정리 약 0.5초 관측을 반영한 내부 배분이며 추가 2초를 더하지 않습니다. native 생성·렌더·close 영구 대기는 별도 실행권을 가진 부모가 종료할 수 있습니다.

OS·커널의 모든 정지를 2초 안에 없앤다는 절대 보장은 아닙니다.

실제 회수를 기한 안에 확인하지 못하면 False와 retiring 참조·OS 핸들을 보존하고 새 GPU 서비스 생성을 거부합니다.

다음 close에서 회수 여부를 다시 확인할 수 있습니다.

자식 crash는 실제 종료 코드와 단계, 자식 예외는 제한된 원문으로 표시하며 자동 재시작하지 않습니다.

종료 요청 전에 이미 확정된 오류 응답은 정상 취소보다 우선 보존합니다.

현재 세대·요청 ID가 일치하는 오류 JSON만 한 번 확인하고, mutex가 즉시 확보되지 않으면 기다리지 않습니다.

이 확인은 같은 종료 기한과 최대 10ms의 짧은 읽기 예산 안에서 수행하며 새 요청이나 프레임 바이트 복사를 시작하지 않습니다.

강제 종료로 실제 잔존 0을 확인한 결과는 자식 renderer.close가 정상 완료됐다는 뜻이 아닙니다.

앞선 콘솔 소스 실행의 실제 GPU 준비는 2.547초, 강제 종료를 사용한 회수는 1.375초였습니다.

현재 pythonw 소스 실행 한 번은 기존 5초 안의 1.813초에 실제 첫 프레임을 받았고, 강제 종료를 사용해 기존 2초 안의 1.265초에 Job 잔존 0·두 후손 핸들의 signaled·감독 스레드 종료·소유 핸들 회 수를 확인했습니다.

모든 환경의 준비 시간이나 정상 GPU 정리를 보장하는 수치가 아닙니다.

소스 모드 결과와 frozen EXE의 재진입·추출 환경·후손 정리는 별도 검증 대상입니다.

## 검사 구분

기존 직접 GPU 검사는 그대로 유지합니다.

기존 FakeRenderer 시험은 서비스/작업자 생성의 명시 factory만 주입하도록 이행했고 원래 단언과 시간 기준을 유지합니다.

배치·날짜 제목·GUI 소유권 fixture는 해당 파일 안에서만 LayoutRenderer를 명시하며 전역 Qt 정리 helper는 바꾸지 않습니다.

실제 프로세스·실제 GPU·실제 화면 검사를 이러한 대역 결과로 대신하지 않습니다.

실제 앱 표시 시험은 기존 main과 같이 최대 5초 준비를 먼저 확인한 뒤, 표시 직전 프레임 수를 기준으로 같은 기존 2초 안에 새 프레임 두 개를 확인합니다.

준비 프레임만으로 표시 후 갱신을 통과시키지 않습니다.

브랜드 재생 시험도 제품의 기존 최대 5초 준비를 사용하며, 준비 뒤 180ms의 실제 영상 변화와 숨김 뒤 70ms의 정지 단언을 그대로 유지합니다.

이 문서는 구현 설명입니다. 독립 verifier 영수증, 전체 검사, frozen 빌드·설치·배포 완료를 자체 승인하는 문서가 아닙니다.
