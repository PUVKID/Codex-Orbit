### LEVEL 3·19차 추가 해설·LEVEL 3·처리 결과와 출력 읽기

실행·대조 순서: 표시된 설정·요청과 실제로 관측한 실행은 다른 근거입니다. 예를 들어 모델을 지정했다는 기록만으로 서버에서 그 모델이 실행됐다고 결론내리지 않습니다.

변경 전·후 모델과 추론 강도, 공개된 이유, 관측 시각과 근거 수준을 함께 읽습니다. 기록되지 않은 값은 미확인으로 남깁니다. 로컬 기록은 서버 모델 신원 증명이 아닙니다.

### LEVEL 3·19차 추가 해설·LEVEL 3·제약과 문제 해결

- 대조 항목 알림이 나타나지 않음: 감시하는 sessions 경로·새 한 줄에 기록 하나를 담는 JSONL 파일 기록·중복 실행 잠금·알림 설정을 확인합니다. 최초 기준선 읽기와 새 변경 감지는 다릅니다.
- 대조 항목 자산 또는 글꼴 오류: 이 차수에서 참조하는 assets와 라이선스를 준비합니다. 소스 이력에는 과거 대용량 그림 한 장 자산이 없을 수 있습니다.
- 대조 항목 이유 또는 이전값이 없음: 원문 기록에 해당 필드가 있는지 확인합니다. 누락된 동기를 추정해서 채우지 않습니다.

### LEVEL 3·19차 추가 해설·LEVEL 3·직전 자료와 전체 비교

### LEVEL 4·19차 추가 해설·LEVEL 4·[src/activity.py](../../../history/19%EC%B0%A8/src/activity.py)

배정 요청과 런타임 관측의 혼합을 피하는 데이터 연결 경계입니다. 전역 상한은 작업 수에 비례한 무제한 증가를 막고 잘못된 상태를 초기화하지 않는 실패 정책을 유지합니다.

**맡은 일과 결과**

- 책임과 출력: 보호문·비공개 표식·긴 인코딩 덩어리는 해석하거나 노출하지 않습니다. [구현 이름 safe_public_text](../../../history/19%EC%B0%A8/src/activity.py#L15)

- 책임과 출력: 원래 기록 시각이 있는 해당 작업 자신의 관측만 보존하도록 책임을 둡니다. 여러 작업을 모두 합쳐 최대 256개이며 작업마다 256개씩 늘리는 제한이 아닙니다. [구현 이름 configuration](../../../history/19%EC%B0%A8/src/activity.py#L76)

- 책임과 출력: 연결 확인에 필요한 앱 기록 항목만 남겨 나 중 대조를 기다립니다. 대화 본문은 보관하지 않으며 모든 작업을 합쳐 대기 자료를 최대 32개로 제한하도록 책임을 둡니다. [구현 이름 defer](../../../history/19%EC%B0%A8/src/activity.py#L160)

- 책임과 출력: 그 작업을 처음 발견한 기록만 추가 정보로 보완하도록 책임을 둡니다. 예를 들어 첫 배정 이유가 늦게 확인되면 처음 행을 보완하며, 뒤에 실제로 바뀐 모델 기록은 별도의 변화로 남깁니다. [구현 이름 observe](../../../history/19%EC%B0%A8/src/activity.py#L273)

**선택값과 제한값**

- 선언과 자원 경계: 보존할 활동 이벤트 수 상한는 **128**입니다. 이 값의 단위와 역할을 다른 모듈의 같은 이름과 혼동하지 않습니다. [MAX_ACTIVITY_EVENTS](../../../history/19%EC%B0%A8/src/activity.py#L7) 원래 선언을 함께 대조합니다: `정의=128`

- 선언과 자원 경계: 이미 본 활동 식별자의 수 상한는 **8192**입니다. 이 값의 단위와 역할을 다른 모듈의 같은 이름과 혼동하지 않습니다. [MAX_ACTIVITY_SEEN](../../../history/19%EC%B0%A8/src/activity.py#L8) 원래 선언을 함께 대조합니다: `정의=8192`

- 선언과 자원 경계: 추적할 활동 호출 수 상한는 **32**입니다. 이 값의 단위와 역할을 다른 모듈의 같은 이름과 혼동하지 않습니다. [MAX_ACTIVITY_CALLS](../../../history/19%EC%B0%A8/src/activity.py#L9) 원래 선언을 함께 대조합니다: `정의=32`

- 선언과 자원 경계: 공개 호출 수 상한는 **128**입니다. 이 값의 단위와 역할을 다른 모듈의 같은 이름과 혼동하지 않습니다. [MAX_PUBLIC_CALLS](../../../history/19%EC%B0%A8/src/activity.py#L10) 원래 선언을 함께 대조합니다: `정의=128`

- 선언과 자원 경계: 연결 확인을 기다리는 활동 수의 전체 상한는 **32**입니다. 이 값의 단위와 역할을 다른 모듈의 같은 이름과 혼동하지 않습니다. [MAX_DEFERRED_ACTIVITIES](../../../history/19%EC%B0%A8/src/activity.py#L11) 원래 선언을 함께 대조합니다: `정의=32`

- 선언과 자원 경계: 시각이 있는 설정 관측 수의 전체 상한는 **256**입니다. 이 값의 단위와 역할을 다른 모듈의 같은 이름과 혼동하지 않습니다. [MAX_CONFIGURATION_SNAPSHOTS](../../../history/19%EC%B0%A8/src/activity.py#L12) 원래 선언을 함께 대조합니다: `정의=256`

**받지 않는 입력과 실패 처리**

- 실패 분기: 활동 호출은 이름과 값의 사전 자료, 연결 대기는 순서 있는 목록이어야 하도록 책임을 둡니다. 어느 한쪽이라도 다른 형식이면 원본을 지우지 않고 오류로 남깁니다. [해당 검사](../../../history/19%EC%B0%A8/src/activity.py#L66) 검사식: `not isinstance(self.data['calls'], dict) or not isinstance(self.data['deferred'], list)`.

- 실패 분기: 시각이 있는 설정 관측은 순서 있는 목록이어야 하도록 책임을 둡니다. 다른 형식이면 원본을 빈 값으로 바꾸어 숨기지 않습니다. [해당 검사](../../../history/19%EC%B0%A8/src/activity.py#L68) 검사식: `not isinstance(self.data['configurations'], list)`.

[SYMBOL_NAMES](../../../history/19%EC%B0%A8/src/brand.py#L110) 원래 선언을 함께 대조합니다: `정의=('model', 'reasoning', 'time', 'reason', 'usage', 'refresh', 'history')`

**받지 않는 입력과 실패 처리**

- 실패 분기: 브랜드 그림 한 변의 크기는 1~512 픽셀이어야하도록 책임을 둡니다. 이 범위를 벗어나면 그림을 만들지 않습니다. [해당 검사](../../../history/19%EC%B0%A8/src/brand.py#L21) 검사식: `not 1 &lt;= size &lt;= 512`.

- 실패 분기: 기능 기호는 모델·추론·시간·이유·한도·새로 고침·이력의 일곱 종류 중 하나이고 크기는 1~96 픽셀이어야하도록 책임을 둡니다. 종류나 크기 중 하나라도 맞지 않으면 거부하도록 책임을 둡니다. [해당 검사](../../../history/19%EC%B0%A8/src/brand.py#L161) 검사식: `name not in SYMBOL_NAMES or not 1 &lt;= size &lt;= 96`.

- 실패 분기: 3D 기능 기호 자산의 파일 명·크기·지문을 적은 명세 문서 크기 오류입니다. 파일 크기는 65,536바이트 이 하여야하도록 책임을 둡니다. 빈 파일도 받지 않습니다. [해당 검사](../../../history/19%EC%B0%A8/src/brand.py#L119) 검사식: `not 0 &lt; path.stat().st_size &lt;= 65536`.

- 실패 분기: 명 세 버전은 참/거짓이 아닌 정수 1이어야하도록 책임을 둡니다. 다른 버전이나 참 값을 1처럼 받아들이지 않습니다. [해당 검사](../../../history/19%EC%B0%A8/src/brand.py#L122) 검사식: `type(metadata.get('schema_version')) is not int or metadata['schema_version'] != 1`.

- 실패 분기: 기호 파일 목록은 이름과 값의 사전이고 일곱 기능 기호의 이름과 정확히 같아야 하도록 책임을 둡니다. 빠진 기호나 추가된 기호가 있어도 거부하도록 책임을 둡니다. [해당 검사](../../../history/19%EC%B0%A8/src/brand.py#L125) 검사식: `not isinstance(files, dict) or set(files) != set(SYMBOL_NAMES)`.

- 실패 분기: 각 기호 정보는 이름과 값의 사전이고 파일 명은 해당 기호 이름에 .png를 붙인 고정 이름이어야하도록 책임을 둡니다. [해당 검사](../../../history/19%EC%B0%A8/src/brand.py#L130) 검사식: `not isinstance(record, dict) or record.get('filename') != name+'.png'`.

- 실패 분기: 파일 내용 지문은 문자열이며 64개의 16 진 수 문자로 이루어져야하도록 책임을 둡니다. 여기서 16 진 수 문자는 0~9와 a~f입니다. 이 검사에서는 소문자만 허용하도록 책임을 둡니다. 숫자·잘못된 길이·다른 문자는 지문으로 받지 않습니다. [해당 검사](../../../history/19%EC%B0%A8/src/brand.py#L133) 검사식: `not isinstance(digest, str) or re.fullmatch('[0-9a-f]{64}', digest) is None`.

- 실패 분기: 3D 기능 기호 읽기 크기 상한 오류입니다. 파일 크기는 262,144바이트 이 하여야하도록 책임을 둡니다. 빈 파일도 받지 않습니다. [해당 검사](../../../history/19%EC%B0%A8/src/brand.py#L136) 검사식: `not 0 &lt; path.stat().st_size &lt;= 262144`.

### LEVEL 4·19차 추가 해설·LEVEL 4·[src/core.py](../../../history/19%EC%B0%A8/src/core.py)

경로의 상위 연결 점 검증과 적용 직전 내용 지문 검사를 결합한 문서 변경 경계입니다. 읽기 경계의 불완전 JSONL은 기록으로 승격하지 않으며 적용·복원은 서로 다른 지문 근거를 사용합니다.

**맡은 일과 결과**

- 책임과 출력: 기록 파일에서 실제 줄바꿈 문자(LF)가 있는 자리만 한 기록의 경계로 봅니다. 읽기 범위의 맨 앞이나 맨 뒤에서 잘린 기록은 완성된 기록처럼 읽지 않습니다. 예를 들어 한 기록 안에 줄바꿈처럼 보이는 특수 문자가 있어도 기록 두 개로 나누지 않습니다. [구현 이름 read_jsonl_tail](../../../history/19%EC%B0%A8/src/core.py#L19)

- 책임과 출력: 공식 앱에서 확인해 저장한 제목과 로컬 색인의 출처를 보존하도록 책임을 둡니다. [구현 이름 title_catalog](../../../history/19%EC%B0%A8/src/core.py#L56)

- 책임과 출력: 자식 작업은 실제 부모 채팅 제목과 작업명을 분리하도록 책임을 둡니다. [구현 이름 resolve_title](../../../history/19%EC%B0%A8/src/core.py#L86)

- 책임과 출력: 지침을 넣을 파일뿐 아니라 그 파일까지 거치는 상위 폴더도 확인하도록 책임을 둡니다. 바로가기처럼 다른 위치로 연결된 파일·폴더(링크 또는 Windows 재분석 지점)가 있으면 적용을 멈춥니다. 예를 들어 선택한 폴더가 다른 폴더로 연결돼 있으면 그곳의 파일을 대신 고치지 않습니다. [구현 이름 safe_path](../../../history/19%EC%B0%A8/src/core.py#L110)

**선택값과 제한값**

- 선언과 자원 경계: 지침 문서의 최대 바이트 수는 **2 * 1024 * 1024**입니다. 바이트는 파일·메모리 크기를 세는 단위이고, 곱셈 표기는 그 크기를 계산하는 식입니다. [MAX_TEXT_BYTES](../../../history/19%EC%B0%A8/src/core.py#L10) 원래 선언을 함께 대조합니다: `정의=2 * 1024 * 1024`

- 선언과 자원 경계: 앱이 관리하는 지침 구역의 시작 표식는 **b'<!-- CODEX-ORBIT:BEGIN -->'**입니다. 이 값의 단위와 역할을 다른 모듈의 같은 이름과 혼동하지 않습니다. [BEGIN](../../../history/19%EC%B0%A8/src/core.py#L11) 원래 선언을 함께 대조합니다: `정의=b'&lt;!-- CODEX-ORBIT:BEGIN --&gt;'`

- 선언과 자원 경계: 앱이 관리하는 지침 구역의 끝 표식는 **b'<!-- CODEX-ORBIT:END -->'**입니다. 이 값의 단위와 역할을 다른 모듈의 같은 이름과 혼동하지 않습니다. [END](../../../history/19%EC%B0%A8/src/core.py#L12) 원래 선언을 함께 대조합니다: `정의=b'&lt;!-- CODEX-ORBIT:END --&gt;'`

**받지 않는 입력과 실패 처리**

- 실패 분기: 문서가 2 MiB 상한을 초과했습니다. 파일 크기는 2MiB 이하여야 하도록 책임을 둡니다. [해당 검사](../../../history/19%EC%B0%A8/src/core.py#L125) 검사식: `path.stat().st_size &gt; MAX_TEXT_BYTES`.

- 실패 분기: 제목 보관 자료와 그 안의 titles 항목은 모두 이름과 값의 사전 자료여야 하도록 책임을 둡니다. 어느 쪽이라도 목록·문자열 등 다른 형식이면 거부하도록 책임을 둡니다. [해당 검사](../../../history/19%EC%B0%A8/src/core.py#L65) 검사식: `not isinstance(cache, dict) or not isinstance(cache.get('titles'), dict)`.

- 실패 분기: 대상 파일 명은 대소 문자를 무시했을 때 AGENTS.md 여야하도록 책임을 둡니다. 다른 이름의 문서에는 적용하지 않습니다. [해당 검사](../../../history/19%EC%B0%A8/src/core.py#L136) 검사식: `target.name.lower() != 'agents.md'`.

- 실패 분기: 대상 문서의 바로 위 폴더가 실제로 있어야 하도록 책임을 둡니다. 없는 폴더에 문서를 새로 만들며 적용하지 않습니다. [해당 검사](../../../history/19%EC%B0%A8/src/core.py#L138) 검사식: `not target.parent.is_dir()`.

- 실패 분기: 대상이 이미 있으면 일반 파일이며 2MiB 이하여야 하도록 책임을 둡니다. 폴더 등 다른 종류이거나 더 크면 적용하지 않습니다. [해당 검사](../../../history/19%EC%B0%A8/src/core.py#L140) 검사식: `target.exists() and (not target.is_file() or target.stat().st_size &gt; MAX_TEXT_BYTES)`.

- 실패 분기: 공백을 제외한 지침 내용이 있어야 하며 추가할 바이트는 2MiB 이하여야 하도록 책임을 둡니다. 빈 내용이나 더 큰 내용은 거부하도록 책임을 둡니다. [해당 검사](../../../history/19%EC%B0%A8/src/core.py#L147) 검사식: `not content.strip() or len(added) &gt; MAX_TEXT_BYTES`.

- 실패 분기: 넣을 지침 안에 앱 관리 구역의 시작 또는 끝 표식이 하나라도 있으면 거부하도록 책임을 둡니다. 구역 경계를 내용이 대신 만들어서는 안 됩니다. [해당 검사](../../../history/19%EC%B0%A8/src/core.py#L149) 검사식: `BEGIN in added or END in added`.

- 실패 분기: 적용 결과가 2 MiB 상한을 초과하도록 책임을 둡니다. [해당 검사](../../../history/19%EC%B0%A8/src/core.py#L163) 검사식: `len(result) &gt; MAX_TEXT_BYTES`.

- 실패 분기: 미리보기 때 파일이 있었는지와 지금 존재하는지가 같아야 하고, 현재 내용의 지문도 예상 지문과 같아야 하도록 책임을 둡니다. 새 파일 생성·삭제·내용 변경 중 하나라도 있으면 새 미리보기가 필요하도록 책임을 둡니다. [해당 검사](../../../history/19%EC%B0%A8/src/core.py#L170) 검사식: `target.exists() != existed or digest(target.read_bytes() if existed else b'') != expected`.

- 실패 분기: 미리보기에 보관한 원문과 적용 예정 내용 각각의 지문이 처음 값과 같아야 하도록 책임을 둡니다. 둘 중 하나라도 바뀌면 적용하지 않습니다. [해당 검사](../../../history/19%EC%B0%A8/src/core.py#L190) 검사식: `digest(plan['original']) != plan['before_hash'] or digest(plan['applied_bytes']) != plan['after_hash']`.

- 실패 분기: 백업은 앱 데이터의 backups 폴더 바로 안에 있는 일반 파일이며 2MiB 이하여야 하도록 책임을 둡니다. 다른 위치나 잘못된 종류·큰 파일은 복원에 쓰지 않습니다. [해당 검사](../../../history/19%EC%B0%A8/src/core.py#L210) 검사식: `backup.parent != safe_path(self.data_dir / 'backups') or not backup.is_file() or backup.stat().st_size &gt; MAX_TEXT_BYTES`.

- 실패 분기: 백업 내용의 지문이 적용 전 원문의 지문과 같아야 하도록 책임을 둡니다. 다르면 원래 문서로 확인할 수 없어 복원하지 않습니다. [해당 검사](../../../history/19%EC%B0%A8/src/core.py#L213) 검사식: `digest(raw) != receipt['before_hash']`.

- 실패 분기: 항목 이름과 값으로 구성된 JSON 자료가 아닙니다. 자료는 항목 이름과 값의 쌍으로 구성되어야 하도록 책임을 둡니다. 순서 있는 목록·단순 문장·숫자를 같은 자료로 받아들이지 않습니다. [해당 검사](../../../history/19%EC%B0%A8/src/core.py#L41) 검사식: `not isinstance(row, dict)`.

- 실패 분기: 이미 있는 관리 구역의 시작 표식과 끝 표식은 각각 정확히 하나이며 시작이 끝보다 앞에 있어야 하도록 책임을 둡니다. 중복·누락·순서 뒤집힘은 거부하도록 책임을 둡니다. [해당 검사](../../../history/19%EC%B0%A8/src/core.py#L156) 검사식: `original.count(BEGIN) != 1 or original.count(END) != 1 or original.index(BEGIN) &gt;= original.index(END)`.

검토 시 구분: 표시된 설정·요청과 실제로 관측한 실행은 다른 근거입니다. 예를 들어 모델을 지정했다는 기록만으로 서버에서 그 모델이 실행됐다고 결론내리지 않습니다.

### LEVEL 4·19차 추가 해설·LEVEL 4·제약과 문제 해결

- 검토 항목 알림이 나타나지 않음: 감시하는 sessions 경로·새 한 줄에 기록 하나를 담는 JSONL 파일 기록·중복 실행 잠금·알림 설정을 확인합니다. 최초 기준선 읽기와 새 변경 감지는 다릅니다.
- 검토 항목 자산 또는 글꼴 오류: 이 차수에서 참조하는 assets와 라이선스를 준비합니다. 소스 이력에는 과거 대용량 그림 한 장 자산이 없을 수 있습니다.
- 검토 항목 이유 또는 이전값이 없음: 원문 기록에 해당 필드가 있는지 확인합니다. 누락된 동기를 추정해서 채우지 않습니다.

### LEVEL 4·19차 추가 해설·LEVEL 4·직전 자료와 전체 비교

검토 시 구분: diff는 두 자료에서 달라진 줄 전체를 보여 주는 파일입니다. +는 추가, -는 삭제를 뜻하며 주석·공백·줄 바꿈도 변경에 포함됩니다. SHA-256은 파일 내용의 지문이고, 큰 그림·실행 파일은 크기와 지문으로 같음을 대조합니다. 지문이 있다는 것만으로 실행에 성공한 것은 아닙니다.

## LEVEL 5 - Expert


### LEVEL 5·19차의 구체적인 기능과 확인

19차는 앱·투명 렌더에서의 SUIT 등록 공통화와 원소·궤도·상태 화면 조정을 기록합니다.

현재 사용자 JSONL과 설정을 입력 받아 변경 감시, 공개 이유·전후 모델 정리, 알림·이력·로컬 진단 기록으로 이어집니다.

감시기는 외부 통신 없이 읽으며 계정 한도는 App Server `account/rateLimits/read`의 별도 읽기 전용 조회입니다.

비율은 남은 토큰 개수가 아니고 로컬 기록은 서버 모델 신원 증명이 아닙니다.

공개 협업 호출·소유자 확인 native 활동, 제한 메모리 원자 프레임, 실제 3D 자산을 공유하는 정적 마크·가시성 모션, 한국 날짜 1~31일 원소, 원본을 보존한 Qt 색 합성, 청 록 화면과 SUIT 글꼴이 보존 범위입니다.

Windows의 차수별 의존성·자산·라이선스가 실행 조건이며 과거 대용량 자산 및 현재 자산 호환성은 보장되지 않습니다. sessions 경로·신규 기록·잠금·알림 설정과 최초 기준 선 여부가 실패 진단 항목입니다.

18차 대비 다섯 소스 수정과 `typography.py` 추가를 전체 diff와 파일 크기·SHA 명세에 연결합니다. 공개 이력에 당시 실행 결과가 없어 실행 여부는 확인 불가입니다. 원문에는 역 적용 후 이전 바이트를 대조한 비교 절차가 기록돼 있으나 이는 당시 앱 실행을 입증하지 않습니다.
