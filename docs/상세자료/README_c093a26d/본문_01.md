### LEVEL 1 · 실제 동작을 따라 읽기

동일한 금속 원자 자산을 공유하는 BrandClock·AnimatedBrand를 추가합니다. 내부 모션은 화면 가시성에 따라 재생을 관리합니다.

로컬 세션 기록에서 모델·추론 강도의 변경과 명시된 배정을 구분합니다. 감시기는 외부 통신 없이 로컬 자료를 읽습니다.

검증된 금속 원자 프레임을 추출 없이 읽는 제한 메모리 재생기입니다.

같은 실제 3D 자산을 공유하는 정적 마크와 가시성 기반 내부 모션입니다.

앱이 소유하는 모든 화면과 대화상자의 공통 무채색 테마입니다.

Codex App Server의 계정 사용 한도를 읽기 전용으로 조회합니다.

제작된 실제 3D 금속 프레임과 고정된 실제 잔량·상태를 합성합니다.

Codex App Server의 `account/rateLimits/read`를 읽기 전용으로 조회합니다. 표시값은 남은 토큰 개수가 아니라 계정 사용 한도 비율입니다.

JSONL은 한 줄마다 하나의 JSON 기록을 담은 파일입니다. CLI는 명령어와 옵션을 입력해 프로그램을 실행하는 방식입니다.

입력 — 현재 사용자 Codex의 로컬 JSONL과 이 차수의 앱 설정

처리 — 변경 감시 → 공개 이유·전후 모델 정리 → 알림·상세창 표시

출력 — 알림·변경 이력·로컬 진단 기록

### LEVEL 1 · 준비하고 확인할 것

Windows와 해당 폴더의 requirements.txt를 기준으로 Python 의존성을 준비합니다. history는 공개 소스 보존 본이며 현재 루트 assets가 과거 모든 차수의 자산과 호환된다는 뜻은 아닙니다.

자산과 의존성을 준비한 이 차수 폴더에서 `python src/app.py`를 실행합니다. history 소스만으로 과거 배포 EXE와 동일한 화면·자산이 모두 복원되지는 않습니다.

### LEVEL 1·17차의 구체적인 기능과 확인

같은 금속 원자 자산을 앱 안의 시계 모양 표시와 움직이는 브랜드 표시에도 함께 씁니다. BrandClock과 AnimatedBrand는 그 표시를 만드는 코드 이름입니다. 내부 화면의 움직임은 창이 실제로 보이는지에 따라 재생을 관리합니다. 고정 마크와 움직이는 표시를 구별해 봅니다.

**입력은 기록 파일, 출력은 알림과 이력입니다.** Codex의 sessions 폴더에는 이 사용자의 작업 기록이 쌓입니다.

앱이 새 기록을 읽으면 이전·이후 모델과 추론 강도, 적혀 있는 이유를 정리해 보여 줍니다.

JSON은 항목 이름과 값을 짝으로 저장하는 자료 형식입니다.

처음 읽은 기록을 출발점으로 삼는 것과 그 뒤 새로 생긴 변경을 알리는 것은 다릅니다.

Windows에서 이 차수의 [requirements.txt](../../../history/17%EC%B0%A8/requirements.txt)에 맞는 Python 의존성과 해당 자산을 준비한 뒤 **이 차수 폴더에서** `python src/app.py`를 실행합니다.

현재 루트의 assets가 과거 모든 차수와 호환되는 것은 아니며, history 소스만으로 과거 EXE의 화면·자산 전체가 복원되는 것도 아닙니다.

확인 순서는 **같은 차수 자료 준비 → 감시 경로 확인 → 새 기록과 알림·상세 대조 → 누락값과 오류 확인**입니다. 예를 들어 기록에 모델 변경이 남았다면 알림의 이전·현재 값과 상세 이력을 비교합니다. 원문에 이유나 이전값이 없다면 모르는 상태로 읽고 채워 넣지 않습니다.

**함께 준비할 도구 버전**: PySide6-Essentials ==6.12.0·PyInstaller ==6.22.3. PySide6는 창을 만드는 도구이고 PyInstaller는 실행 파일을 묶는 도구입니다. 외부 실행 도구·GPU 드라이버는 별도 조건입니다.

**멈추거나 거부되는 조건과 읽는 방법**

- 오류 “같은 데이터 폴더의 Codex Orbit가 이미 실행 중이거나 잠금 파일에 접근할 수 없습니다.”

한 설정·상태 파일을 두 실행이 동시에 바꾸지 않도록하며, 이 메시지만으로 어느 쪽 원인인지 확정하지 않습니다.

정확한 조건은 [`not lock.tryLock(100)`](../../../history/17%EC%B0%A8/src/app.py#L1212) (src/app.py)에서 확인할 수 있습니다.

- 오류 “앱 설정은 JSON 객체여야 합니다.”

  앱 설정이 항목 이름과 값을 가진 사전이어야 합니다. 예를 들어 목록만 저장돼 있으면 설정 이름으로 값을 찾을 수 없어 거부합니다. 정확한 조건은 [`not isinstance(value, dict)`](../../../history/17%EC%B0%A8/src/app.py#L169) (src/app.py)에서 확인할 수 있습니다.

- 오류 “원자 자산 매니페스트에 중복 필드가 있습니다.”

  금속 원자 자료 명세에서 같은 항목 이름이 두 번 나오면 거부합니다. 어느 값을 믿을지 불명확한 문서를 마지막 값만 골라 정상으로 읽지 않기 위한 조건입니다. 정확한 조건은 [`key in value`](../../../history/17%EC%B0%A8/src/atom_frames.py#L44) (src/atom_frames.py)에서 확인할 수 있습니다.

- 오류 “원자 자산 매니페스트 크기가 허용 범위를 벗어났습니다.”

  금속 원자 명세는 비어 있지 않고 64 KiB 이하여야 합니다.

파일 목록과 지문을 적은 작은 명세 자체가 지나치게 크거나 빈 경우 거부해 이후 그림 검증의 전제를 확인합니다.

정확한 조건은 [`not 0 &lt; manifest_path.stat().st_size &lt;= MAX_MANIFEST_BYTES`](../../../history/17%EC%B0%A8/src/atom_frames.py#L69) (src/atom_frames.py)에서 확인할 수 있습니다.

- 오류 “원자 자산 매니페스트는 객체여야 합니다.”

  금속 원자 명세는 이름과 값이 짝지어진 사전이어야 합니다.

단순 목록이나 글 한 줄을 필요한 파일·지문을 적은 정상 명세로 받아들이지 않습니다.

- 오류 “원자 프레임 ZIP의 SHA256 형식이 잘못됐습니다.”

  금속 원자 파일 지문은 0~9와 a~f로 쓴 64 자리 SHA-256 문자열이어야합니다.

잘못된 길이나 다른 종류의 값을 지문이라고 받아들이지 않습니다.

SHA-256은 파일 내용 비교 값이며 성능 점수가 아닙니다.

정확한 조건은 [`not isinstance(digest, str) or re.fullmatch('[0-9a-f]{64}', digest) is None`](../../../history/17%EC%B0%A8/src/atom_frames.py#L85) (src/atom_frames.py)에서 확인할 수 있습니다.

  금속 원자 압축파일은 비어 있지 않고 원문에 정한 최대 바이트 크기 이하여야 합니다.

이 크기는 압축을 풀기 전 파일 자체이며, 해제 후 전체 자료량과 별도 제한입니다.

- 오류 “원자 프레임 ZIP의 SHA256이 일치하지 않습니다.”

  금속 원자 파일의 실제 내용으로 계산한 지문이 명세와 다르면 거부합니다.

같은 이름이더라도 바뀌었거나 다른 자료일 수 있으므로 정상 자산으로 조용히 계속 쓰지 않습니다.

정확한 조건은 [`hasher.hexdigest() != digest`](../../../history/17%EC%B0%A8/src/atom_frames.py#L94) (src/atom_frames.py)에서 확인할 수 있습니다.

- 오류 “원자 프레임 ZIP의 정확한 540개 이름·목록이 일치하지 않습니다.”

  금속 원자 압축 묶음은 정확히 540장과 정해진 파일 이름 목록을 모두 갖춰야합니다.

한 장이 빠지거나 다른 이름이 섞인 경우 재생 자료가 다르므로 거부합니다.

장수만 맞추고 파일 이름을 무시하는 검사는 아닙니다.

정확한 조건은 [`len(members) != FRAME_COUNT or {item.filename for item in members} != names`](../../../history/17%EC%B0%A8/src/atom_frames.py#L100) (src/atom_frames.py)에서 확인할 수 있습니다.

- 오류 “원자 프레임 전체 읽기 상한을 초과했습니다.”

  금속 원자 압축을 푼 전체 그림의 바이트 합이 원문 상한을 넘으면 거부합니다.

압축파일이 작아도 풀린 양은 클 수 있어 한 장 제한·원래 ZIP 크기와 별도로 검사합니다.

정확한 조건은 [`sum(item.file_size for item in members) &gt; MAX_TOTAL_BYTES`](../../../history/17%EC%B0%A8/src/atom_frames.py#L102) (src/atom_frames.py)에서 확인할 수 있습니다.

  금속 원자 자료가 검증 뒤 실행 중 바뀌면 계속 쓰지 않습니다.

처음 확인한 파일과 현재 파일이 다르므로 다시 앱을 시작해 새 자료를 확인해야 하는 조건입니다.

이행은 저장 형식을 바꾸는 과정이며 다른 원본을 같은 자료처럼 취급하지 않습니다.

정확한 조건은 [`backup.read_bytes() != original`](../../../history/17%EC%B0%A8/src/notifier.py#L104) (src/notifier.py)에서 확인할 수 있습니다.

- 오류 “이전 상태의 파일 위치가 올바르지 않습니다. 자동 초기화하지 않습니다.”

  이전 기록에서 읽어 둔 시작·끝 위치가 참·거짓, 정수가 아닌 값 또는 음수라면 거부합니다.

파일의 몇 번째 바이트부터 읽을지를 알 수 없으므로 0으로 임의 초기화하지 않습니다.

정확한 조건은 [`any(isinstance(v, bool) or not isinstance(v, int) or v &lt; 0 for v in (offset, end))`](../../../history/17%EC%B0%A8/src/notifier.py#L111) (src/notifier.py)에서 확인할 수 있습니다.

- 오류 “JSON 객체가 아닙니다.”

  한 건의 기록은 항목 이름과 값이 짝지어진 객체여야 합니다.

예를 들어 숫자 하나나 문자열만 온 경우 이름별 필드를 읽을 수 없어 정상 기록으로 받지 않습니다.

정확한 조건은 [`not isinstance(record, dict)`](../../../history/17%EC%B0%A8/src/notifier.py#L435) (src/notifier.py)에서 확인할 수 있습니다.

- 오류 “명시 알림 파일 상한 초과”

  명시 배정 알림 파일이 20,000바이트를 넘으면 거부합니다. 짧은 알림 전달 파일을 큰 본문 저장소처럼 읽지 않게하기 위한 크기 제한입니다. 정확한 조건은 [`path.stat().st_size &gt; 20000`](../../../history/17%EC%B0%A8/src/notifier.py#L500) (src/notifier.py)에서 확인할 수 있습니다.

- 오류 “객체가 아닌 응답”

  계정 서버의 응답이 이름별 값을 가진 객체가 아니면 한도 자료로 읽지 않습니다. 숫자·문자열만 온 응답에서 비율을 임의로 만들지 않습니다. 정확한 조건은 [`not isinstance(message, dict)`](../../../history/17%EC%B0%A8/src/usage.py#L226) (src/usage.py)에서 확인할 수 있습니다.

**알림이 없거나 값이 비어 있을 때**: 감시 sessions 경로·새 JSONL 기록·중복 실행 잠금·알림 설정을 순서대로 확인합니다.

최초 기준 선 읽기와 새 변경은 다릅니다.

자산·글꼴 오류라면 이 차수 assets와 라이선스를 대조합니다.

과거 대용량 프레임 자산이 소스 이력에 없을 수 있습니다.

이유·이전 값이 없으면 원 문 필드를 확인하며 동기를 추정하지 않습니다.

설정·이력·로컬 진단은 개인 운영자료입니다. 다른 사람에게 공유하기 전에 포함된 내용을 확인합니다. **로컬 기록은 서버 모델 신원 증명이 아닙니다.**

### LEVEL 2·17차의 구체적인 기능과 확인

자산 공유는 서로 다른 화면의 형태를 연결하고, 가시성 기반 관리는 보이지 않는 내부 모션의 재생 상태와 연결됩니다. 같은 자산이라고 모두 같은 타이머·수명을 가지는지는 구현에서 확인해야 합니다. 위젯과 내부 브랜드의 동작 범위를 나눠 읽습니다.

**수집·해석·표시·보존**을 연결해 읽습니다. 로컬 JSONL의 관측 변경과 명시된 배정은 다른 종류의 근거입니다. 감시기는 외부 통신 없이 로컬 자료를 읽습니다. 별도 usage 모듈의 계정 한도 조회는 App Server 읽기 전용 경로이므로 이 로컬 감시와 구별합니다.

Windows에서 이 차수의 [requirements.txt](../../../history/17%EC%B0%A8/requirements.txt)에 맞는 Python 의존성과 해당 자산을 준비한 뒤 **이 차수 폴더에서** `python src/app.py`를 실행합니다.

현재 루트의 assets가 과거 모든 차수와 호환되는 것은 아니며, history 소스만으로 과거 EXE의 화면·자산 전체가 복원되는 것도 아닙니다.

**이 보관본 의존성 선언**: PySide6-Essentials ==6.12.0·PyInstaller ==6.22.3. PySide6는 창을 만드는 도구이고 PyInstaller는 실행 파일을 묶는 도구입니다. 외부 실행 도구·GPU 드라이버는 별도 조건입니다.

해당 프레임 자산을 준비한 뒤 내부 화면의 BrandClock·AnimatedBrand를 확인합니다. 화면을 보이게하거나 숨겼을 때 내부 모션 상태를 비교하고 정적 마크와 혼동하지 않습니다. 공개 보존 본만으로 당시 배포 자산·실행 화면이 전부 복원된다고 가정하지 않습니다.

Windows에서 이 차수의 [requirements.txt](../../../history/17%EC%B0%A8/requirements.txt)에 맞는 Python 의존성과 해당 자산을 준비한 뒤 **이 차수 폴더에서** `python src/app.py`를 실행합니다.

현재 루트의 assets가 과거 모든 차수와 호환되는 것은 아니며, history 소스만으로 과거 EXE의 화면·자산 전체가 복원되는 것도 아닙니다.
